# ADR-0005: Paste-back

Status: Accepted (2026-11-16). S-7 (TASK-010) and S-2/S-5 interact.

## Context
FR-003-15 defines the paste sequence for the Library; FR-005-14 uses the same posting step for trigger expansion, and item hotkeys (FR-005-01) paste the same way. FR-001-03 requires own-write markers on every Flotsam pasteboard write. Without Accessibility the app can only copy (FR-008-14).

## Decision
`Paste` (L2) owns the one implementation. Library, Shortcuts and Triggers call it; none re-implements any step.
- API: `PasteService.paste(item:, mode:, target:) async -> Result<PasteOutcome, FlotsamError>`. Modes: `.paste` (all representations), `.plainText`, `.copyOnly` (steps 1 to 5 only, ⇧Return and the no-Accessibility fallback).
- Sequence: resolve and validate (file members), write to the pasteboard through `PasteboardPort` with markers `org.nspasteboard.AutoGeneratedType` and `com.flotsam.own-write` and record the returned `changeCount`, update `pasteCount`/`lastUsedAt` in Storage, hide the panel, wait until not visible plus 40 ms, confirm the frontmost app is still the recorded target within 250 ms, then post ⌘V (key code 9, Command flag, down then up) through `KeyEventPoster.postPaste(to:)`, addressed to the target process with `CGEvent.postToPid` (the adapter re-checks that the target is still frontmost and running first), not to the session event tap, so a focus change after the check cannot redirect the clip (FR-003-16).
- The target app is recorded by the app target when the panel or hotkey is invoked (`FrontmostAppProvider` port), never re-derived at paste time.
- Permission check (`AXIsProcessTrusted`) is a port (`PermissionProbe`); not trusted means `.copyOnly` plus the `LIB-PRM` or `TRG-PRM` message by the caller. The decision and its `SET-PRM-001` error have one owner, `PasteGate` in Base (`PasteGate.isAllowed(probe:)`, `PasteGate.copyOnlyError(itemId:)`; the gate only decides, `PasteOutcome` is the one paste-result type); `PasteService`, the Library, Shelf and item-hotkey callers, trigger expansion and the Triggers pane notice all ask it, and none tests the permission or builds the error itself (TASK-434).
- Trigger expansion adds before and after steps (variables, clipboard snapshot and restore, Backspaces) in `Triggers`, but its ⌘V step is a call to `PasteService.postPaste(target:)`, the same function.
- Every key Flotsam synthesises is pid-addressed, not only ⌘V (TASK-426, security F4b). `TriggerKeyPoster` extends `KeyEventPoster`, and `postKeyPress(keyCode:count:to:)` and `postText(_:to:)` take the target like `postPaste(to:)`. The one adapter (`CGEventKeyPoster`) has a single private post step shared by all three: it re-checks that the target is frontmost and running, then calls `CGEvent.postToPid`. Nothing in the app posts to the session event tap. A mismatch posts nothing and returns false.

## Alternatives rejected
- **Accessibility API `AXUIElement` set-value insertion.** Does not work in Terminal, Electron and many web fields; ⌘V works everywhere an app already accepts paste.
- **Each caller posting its own ⌘V.** Three copies of a timing-sensitive rule; the 40 ms and 250 ms values are tuned from one dogfood matrix (FRD-003 Assumption 2) and must change in one place.
- **⌘V (and trigger Backspaces, boundary re-posts and re-types) posted to the session event tap.** Delivered to whatever app is frontmost at post time, so a focus change after the 250 ms check could paste the clip, or delete characters, in the wrong app (TASK-423 F4, TASK-426 F4b). Chosen instead: `CGEvent.postToPid`. Trade-off: `postToPid` reports no delivery failure, so an app that ignores pid-addressed events gets no paste and no LIB-OS-001 (FR-003-16); the dogfood matrix covers Terminal, Electron and sandboxed targets.

## Consequences
The window constants (40 ms settle, 250 ms target check, 10 ms Backspace-to-paste gap) live in `PasteTiming` in Paste, tuned by the dogfood matrix. If spike S-7 shows a non-activating panel cannot take text, the panel changes in the app target (e.g. activating panel with explicit refocus); `PasteService` is unchanged except that "target" recording becomes mandatory-before-activation, which it already is.

## Reversibility
High.
