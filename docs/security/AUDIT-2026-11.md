# Flotsam security audit, November 2026 (Phase 9S, TASK-345)

Audited commit: origin/main at aef0135 (includes 42ec312 and 017ec03). Audit date: 2026-11-18. Auditor: Odo (security engineer agent). Method: reading the source, building the Debug app with `bin/build.sh`, inspecting the built binary, running targeted tests. The app was not launched.

## Verdict

Conditional ship. There are no P0 or P1 findings, and the condition is already on the books: TASK-009 (verify the default ignored-app bundle ids, filed as must-complete-before-release and still pending) must be done before a release goes out. The three fixes from the earlier review (F1, F4, F5) are present on main and covered by passing tests. The zero-network claim holds in source and in the built binary. Three P2 items and two P3 items are open; apart from TASK-009 none blocks release, and each is recorded so the decision to accept it is explicit.

Severity scale: P0 is data exposed, a credential leak or an auth bypass; P1 is a weak protection or missing defense; P2 is a best-practice gap; P3 is hygiene. The earlier review used Critical, High, Medium and Low for the same four levels.

## Findings

### F-01 (P2): Deleting a single item does not remove the plaintext recovery copies

Pre-migration copies and `corrupt-<timestamp>` quarantines are full plaintext copies of the database. Fix F1 made Clear History remove both (`Packages/FlotsamCore/Sources/FlotsamStorage/Retention/ClearHistory.swift:162`, calling `purgePlaintextCopies` in `Folder/PlaintextCopies.swift:69`) and made them expire: a pre-migration copy 7 days after a later clean launch that ran no migration, a quarantine 30 days after its name stamp (`PlaintextCopies.swift:79`, called from `Database/FlotsamDatabase.swift:93`). Per-item deletion (`Deletion/ItemDeletion.swift:20`) does not reference these copies (grep for PlaintextCopies, preMigration and quarantine in `Deletion/` returns nothing). So an item the user deleted can survive in a recovery copy for up to 30 days. This is the accepted residual of the F1 fix, but it contradicts the user's expectation of "delete means gone". Remediation: either say so in the delete confirmation and FRD-007, or have per-item delete trigger a copy purge when copies exist. Needs an owner decision. Ticket: TASK-484.

### F-02 (P2): Data at rest is not encrypted and the app is not sandboxed

The database, blobs and thumbnails are plain files. Protection is mode 0700 on folders and 0600 on files (`Folder/DataFolder.swift:7-8`) plus whatever FileVault provides. Any process running as the same user can read them. The app cannot be sandboxed by design (CGEventTap, Accessibility paste-back, arbitrary screenshot folders, per `docs/ARCHITECTURE.md`). Concealed, transient and auto-generated pasteboard content is never stored (see check 3), which removes the highest-value secrets. Accepted by design. Remediation if the position changes: SQLCipher or per-file encryption with a Keychain key, at a cost to FR-007 search and backup behavior. No ticket.

### F-03 (P2): Ignored-app protection depends on bundle ids that were never verified

`SettingValues.swift:116` ships six default ignored bundle ids (Keychain Access, Passwords, 1Password 8 and 7, Bitwarden, KeePassXC). The comment above them and FRD-008 section 9 item 2 record that they have not been checked against real installs (spike TASK-009). A wrong id fails silently: the password manager's copies would be stored. The match itself is correct: `ClipboardCapture.swift:285-286` resolves the source and skips on a match. When the writing app does not supply the `org.nspasteboard.source` marker, `resolveSource` falls back to the frontmost app (`ClipboardCapture.swift:338-352`), so detection still works for apps that omit the marker, with the usual race if focus moved between copy and poll. Most of these apps also mark their copies concealed, which is caught by an independent check. Remediation: finish TASK-009 (high priority, pending, no checkpoint yet). This is the release condition.

### F-04 (P3): The trigger word buffer is not zeroed

The keystroke tap (`App/Platform/EventTapKeySource.swift:62`, session tap, default tap, needs Accessibility) feeds an in-memory word buffer capped at 24 characters (`Packages/FlotsamCore/Sources/FlotsamTriggers/TriggerGrammar.swift:15`). The buffer is never persisted or logged (`Tests/FlotsamTriggersTests/TriggerPrivacyTests.swift`, FR-005-20). Matches and expansions are suppressed in excluded apps and while Secure Event Input is on, and macOS withholds keystrokes from taps during Secure Event Input. The remaining exposure is that up to 24 recent characters can stay in process memory after a word ends, and characters can be buffered in an excluded app before the exclusion check suppresses the match. Only a same-user process able to read this app's memory could use that, which already implies a debugger entitlement or root. Remediation: clear the buffer on boundary and on excluded-app focus. Ticket: TASK-485.

### F-05 (P3): Developer ID signing and notarization were not exercised

`bin/release.sh` signs with `--options runtime`, the (empty) entitlements file and a secure timestamp when a Developer ID identity and a notary keychain profile exist; it submits with `notarytool` using the keychain profile (no password on the command line), staples, runs `spctl`, and writes a SHA-256. The script's design is correct on reading. This audit had no Developer ID identity, so the notarized artifact was not produced or assessed. Remediation: run the release on the signing machine and attach `codesign -dvv` output (expect flags `runtime`) and `spctl -a -vv` (expect `Notarized Developer ID`) to the release record. Ticket: TASK-486.

## Checks and evidence

### 1. No network code

Source grep (Packages/FlotsamCore/Sources and App/) for URLSession, NSURLSession, URLRequest, Network framework, NWConnection, NWListener, sockets (socket, connect, getaddrinfo), CFStream, CFSocket, WKWebView, WebKit, and analytics or crash SDK names found no use. The only URL literal in the app is the project page link at `App/Flotsam/Settings/SettingsEnvironment.swift:77`, which is handed to the system to open in the user's browser; the app itself makes no request.

Built binary (Debug, `bin/build.sh`, `BUILD SUCCEEDED`). Commands run against `build/Build/Products/Debug/Flotsam.app/Contents/MacOS/`:

- `otool -L Flotsam` lists only `Flotsam.debug.dylib` and `libSystem`. `otool -L Flotsam.debug.dylib` (the app code) lists Foundation, AppKit, ApplicationServices, Carbon, Combine, CoreFoundation, CoreGraphics, CoreServices, CryptoKit, DeveloperToolsSupport, ImageIO, ServiceManagement, SwiftUI, libsqlite3 and the Swift runtime libraries. No CFNetwork, Network, WebKit or Security-transport framework is linked.
- `nm -u` on both binaries, filtered for NSURLSession, NSURLConnection, CFNetwork, CFStream, CFSocket, nw_connection, nw_listener, nw_endpoint, socket, connect, getaddrinfo, gethostbyname, WKWebView, NWConnection and URLSession, returned nothing. `__preview.dylib` has no symbols.
- `strings -a Flotsam.debug.dylib | grep -E 'https?://'` returns only the project page URL above.
- The app bundle has no Frameworks directory; GRDB is statically linked.

Foundation and AppKit can reach the network indirectly, so linkage alone is not a proof; the source grep and the unresolved-symbol check together are the evidence. Result: no network code. This supports anti-truths A1 (no sync, no server) and A4 (no telemetry or analytics) in `docs/TRUTHS.md`.

### 2. Entitlements, Info.plist, hardened runtime

- `App/Flotsam/Flotsam.entitlements` is an empty `<dict/>`; `project.yml` declares `properties: {}`. No sandbox, no network client or server, no device, no Apple Events, no library validation exception, no JIT or unsigned-memory exception. Not sandboxed, by design (F-02).
- `App/Flotsam/Info.plist` has no usage-description keys, no `NSAppTransportSecurity` key, `LSUIElement` true, `LSMinimumSystemVersion` 14.0.
- `project.yml` sets `ENABLE_HARDENED_RUNTIME: YES`, and `bin/release.sh` signs with `--options runtime`. To show the flag takes effect with this entitlements file, a scratch copy of the Debug app was re-signed ad hoc with `codesign --force --deep --options runtime --entitlements App/Flotsam/Flotsam.entitlements --sign -`; `codesign -dvv` then reported `flags=0x10002(adhoc,runtime)`. The plain Debug build reports `flags=0x20002(adhoc,linker-signed)` with no runtime flag, as expected for an unsigned Debug build. The real release signature is F-05.

### 3. Pasteboard privacy

- Marker constants: `Packages/FlotsamCore/Sources/FlotsamBase/Pasteboard/OwnWriteLedger.swift:5-20`. `neverStore` is concealed, transient and auto-generated.
- Enforcement in `Packages/FlotsamCore/Sources/FlotsamCapture/ClipboardCapture.swift`: own writes skipped at 273 and 282, `neverStore` types skipped at 283 (code CAP-POL-001), ignored app skipped at 286 (CAP-POL-002). All three run before any content is read.
- Tests (all in `Packages/FlotsamCore/Tests/FlotsamCaptureTests/`): `FRD001ContractTests.swift` (OC-1012 to OC-1015), `FRD001ContractPart2Tests.swift`, `ClipboardCaptureTests.swift`, `Frd000PasteboardCallsiteTests.swift` (OC-0037), `GapHandoffTests.swift`, and `FRD005ContractTestsSaveClipboard.swift` for the Save Clipboard path. See F-03 for the ignored-app caveat.

### 4. Database permissions, log redaction, diagnostics

- Modes: folders 0700 and files 0600 (`DataFolder.swift:7-8`). `flotsam.sqlite` is created 0600 before first open so the `-wal` and `-shm` files inherit it (`prepareDatabaseFiles`, `DataFolder.swift:120-127`). Blobs and thumbnails are written through `BlobStore.writeAtomically` (`Blobs/BlobStore.swift:53-57`) with `DataFolder.filePermissions`, so thumbnails are 0600. SQLite `secure_delete` is ON (`Database/FlotsamDatabase.swift:341`). Tests: `Tests/FlotsamStorageTests/DataFolderLayoutTests.swift`, `Adversarial370QuarantineTests.swift`.
- Logging: `Packages/FlotsamCore/Sources/FlotsamBase/Logging/FlotsamLog.swift` is the only `Logger` user (line 178). Values pass through a closed `LogSafeValue` allowlist; anything else is marked private; trace output is DEBUG-only. Tests: `Tests/FlotsamBaseTests/Adversarial000Tests.swift` (privacy section, FR-000-10), `LoggingMutationTests.swift`, `Tests/FlotsamCaptureTests/GapSentinelTests.swift` (clip content never reaches a log or signpost), and `FRD002GapTests231_232.swift` (no screenshot filename or folder name in the diagnostics report).
- Diagnostics: `FlotsamBase/Diagnostics/DiagnosticsReport.swift` and `DiagnosticsSnapshotBuilder.swift` build a closed-field report (error codes, counts, app version, macOS version and CPU architecture). It contains no clip content, titles, paths or filenames. It is placed on the pasteboard only when the user chooses Copy; nothing is written to disk or sent. There is no crash reporter or MetricKit upload.

### 5. Dependencies

- `Packages/FlotsamCore/Package.resolved` pins GRDB.swift 7.12.0 (revision 92a554c, exact version in `Package.swift`). It is the only third-party dependency.
- GRDB 7.12.0 is the latest release (published 2026-11-01; previous 7.11.1, 2026-06-18).
- `gh api repos/groue/GRDB.swift/security-advisories` returns an empty list (no published advisories). A web search on 2026-11-18 for GRDB CVEs and advisories returned nothing about GRDB; that is absence of evidence from a general search, not a database lookup, and the empty advisories list is the stronger signal.
- The app links the system `libsqlite3.dylib` (seen in `otool -L`), so SQLite fixes arrive with macOS updates, not with GRDB. Users on an unpatched macOS 14 carry the SQLite version of that release. Informational.

### 6. Re-verification of F1, F4, F5

`git merge-base --is-ancestor` confirms 42ec312 and 017ec03 are both ancestors of origin/main.

- F1 (plaintext database copies): closed for Clear History and expiry. `PlaintextCopies.swift:69` and `:79`, `ClearHistory.swift:162`, `FlotsamDatabase.swift:93`; tests in `Tests/FlotsamStorageTests/PlaintextCopiesTests.swift`. Residual for single-item deletion is F-01.
- F5 (folder and file modes): closed. `DataFolder.swift:74`, `:81` enforce 0700 on every launch (`enforceMode`, line 101); `:120-127` enforce 0600 on the database files; `DataFolderLayoutTests.swift`.
- F4 (paste-back to the wrong app): closed. `App/Platform/CGEventKeyPoster.swift:18-21` and `:61-68` post with `CGEvent.postToPid(target.processId)` instead of the session tap, after re-checking that the target is frontmost and running; a mismatch posts nothing and returns the FR-003-16 failure. `Packages/FlotsamCore/Sources/FlotsamPaste/PasteService.swift:157` passes the target through; trigger expansion shares that path. Tests added in `Tests/FlotsamPasteTests/PasteServiceTests.swift`.

Test run: `swift test --filter 'PlaintextCopiesTests|DataFolderLayoutTests|PasteServiceTests|FRD001ContractTests|TriggerPrivacyTests|GapSentinelTests|LoggingMutationTests'` in `Packages/FlotsamCore`: all suites passed (115 tests, exit 0). The `CGEvent` posting itself cannot be proven by a unit test without a second running app; the tests use a fake poster and assert the target is passed. That gap is inherent and is covered by manual QA, not by this audit.
