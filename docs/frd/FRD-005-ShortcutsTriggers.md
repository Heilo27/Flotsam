# FRD-005 — Shortcuts and Triggers

**Status:** Draft · 2026-11-16 · Constitution: [TRUTHS.md](../TRUTHS.md) · PRD: [PRD.md](../PRD.md) (feature F5) · Errors: [FRD-000](FRD-000-ErrorSystem.md)
**Owns:** the global hotkey registry (single definition), shortcut validation, per-item hotkeys, the trigger grammar, typed-trigger detection and expansion, variables, the event tap and its health, the default trigger-excluded apps.
**Does not own:** the paste-event posting procedure and the target-app check ([FRD-003](FRD-003-Library.md) FR-003-15, FR-003-16); own-write markers ([FRD-001](FRD-001-Capture.md) FR-001-03); the Library, Shelf and Curated behaviours these hotkeys invoke ([FRD-003](FRD-003-Library.md), [FRD-006](FRD-006-Shelf.md), FR-001-19); permission onboarding and the settings screens ([FRD-008](FRD-008-OnboardingSettings.md)); storage of the `hotkey` and `trigger` fields and their retention exemption ([FRD-007](FRD-007-RetentionStorage.md)).

## Truth Test
- Serves: S4 — a saved clip gets a hotkey or a typed trigger and becomes zero-search.
- Supports: P1 — the open-Library and Save Clipboard hotkeys are the entry to the 3-second path; per-item hotkeys are its fastest case.
- Violates: none, provided scope stays inside A2 (no scripts, forms, nested snippets, cursor placement, fill-ins or date math: see Out of Scope) and A4 (no network). Typed triggers observe keystrokes, so they are bounded by FR-005-10 (no tap unless a trigger exists) and FR-005-20 (keystroke privacy).
- Verdict: KEEP. Sequencing note for Friday: S4 is secondary and the primary (F3) must ship first. This FRD is KEEP, not DEFER, but build order is hotkey registry and per-item hotkeys first, typed triggers last. Typed triggers are the highest-risk feature (S4 falsifier: misfires in terminal, browser, IDE) and may be cut from v1.0 without affecting any other FRD.

## 1. Purpose
Let any saved clip be pasted with one key chord or by typing a short word, in any app, and give the app's own actions (open Library, save the clipboard, toggle the Shelf) a global entry point, without ever misfiring in terminals, password fields or chat boxes.

## 2. User Stories
- As a user, I press one chord from any app and the Library opens.
- As a user, I give my email signature the trigger `;sig`, type it in a mail window followed by Space, and the signature appears with its links intact.
- As a user, I give a clip a hotkey and press it to paste that clip into whatever I am typing in.
- As a user, I use `{date}` in a clip so a standup template carries today's date when pasted.
- As a user, I type `;sig` in a terminal or a password field and nothing is changed.
- As a user in Curated capture mode, I press a chord to save what is on the clipboard now.

## 3. Functional Requirements

**Hotkey registry and rules**
- **FR-005-01** Registry (the only list of hotkeys). Global hotkeys are exactly these, each with a settings key (FRD-008 registry) and an action:

  | Id | Settings key | Default | Action |
  |---|---|---|---|
  | openLibrary | `shortcuts.openLibrary` | ⌃⌘V | toggle the Library (FRD-003 FR-003-02) |
  | saveClipboard | `shortcuts.saveClipboard` | none | FR-005-06 |
  | addClip | `shortcuts.addClip` | none | open the Add Clip window (FRD-004 FR-004-19) |
  | toggleShelf | `shortcuts.toggleShelf` | none | show or hide the Shelf (FRD-006) |
  | pasteQueue | `shortcuts.pasteQueue` | none | paste the next item of the paste queue (FRD-003 FR-003-25); like item hotkeys it is off while a Flotsam window is key (FR-005-05) |
  | item hotkey (one per item, optional) | stored on the item | none | FR-005-05 |

  Only `openLibrary` has a default. The default is provisional until the conflict spike in Assumptions is done. A binding can be cleared (action unreachable by hotkey, still reachable from the menu bar menu) except `openLibrary`, which can be changed but not cleared (the Library must stay reachable from the keyboard).
- **FR-005-02** Binding rules (single definition). A shortcut is one key plus a modifier set. It is valid when: (a) the modifier set contains ⌘ or ⌃ (⇧ and ⌥ may be added; ⌥ or ⇧ alone, or ⌥⇧ alone, are rejected because macOS refuses them for global registration (since macOS 15, so on every supported version)); (b) the key is a non-modifier key (letters, digits, punctuation, F1 to F20, arrows, Space, Return, Tab, Escape, Delete); (c) it is not on the reserved list: ⌘Q, ⌘W, ⌘H, ⌘M, ⌘Tab, ⌘Space, ⌃Space, ⌘⌥Esc, ⌘, (comma), and ⌘ plus any of C, V, X, Z, A with no other modifier; (d) it is not an enabled macOS symbolic hotkey as returned by `CopySymbolicHotKeys()` (Mission Control, Spotlight, screenshots and so on). Violations of (a) to (d) → `TRG-VAL-003`. A shortcut equal to another in the registry or on another item (compared by key code and modifiers) → `TRG-VAL-004`. Validation happens before registration and is inline in the editor or recorder; a rejected binding is never saved.
- **FR-005-03** Registration. Global hotkeys use Carbon `RegisterEventHotKey` (no Accessibility or Input Monitoring needed). They are registered at launch and on change, and unregistered on clear, on item deletion and on quit. If the OS refuses registration (`TRG-OS-001`), the binding is kept (not cleared), shows a warning badge in Settings or the item editor, and registration is retried at the next launch, on wake and when the user re-saves it. A failed binding never blocks other bindings.
- **FR-005-04** Recorder. The Shortcut recorder control (Settings and the item editor) captures the next chord while focused. While any recorder is recording, all of Flotsam's global hotkeys are unregistered, and they are re-registered when it ends. Esc cancels; Delete or Backspace clears (where clearing is allowed, FR-005-01); a chord that fails FR-005-02 shows the code message inline and keeps recording. The inline message clears when recording starts and whenever it ends (an accepted chord, Esc, Delete, or the recorder losing focus), so a rejected chord's error never stays beside a binding that was then accepted. The recorder never records a chord that only includes modifiers.

**Hotkey actions**
- **FR-005-05** Item hotkey. Pressing a registered item hotkey pastes that item into the frontmost application without opening any Flotsam window. The target is the frontmost application at key-down time. Sequence: FRD-003 FR-003-15 steps 1 to 4 and 6 (resolve files, write the pasteboard with own-write markers, bump `pasteCount` and `lastUsedAt`, post ⌘V after the settle delay if the target is still frontmost), with the panel steps omitted. Text-bearing items first have variables expanded (FR-005-17). Any item kind may carry a hotkey. When Accessibility is missing, the item is copied only and `SET-PRM-001` shows (FRD-003 FR-003-17 behaviour). A missing file member → `LIB-DAT-001` per FRD-003. Previous clipboard contents are restored per FR-005-16 once ⌘V has been posted; when the item was only copied (Accessibility missing) or ⌘V could not be posted (`LIB-OS-001`), nothing is restored and the item stays on the pasteboard so the user can paste it. Item hotkeys are suspended while a Flotsam panel or Settings window is key.
- **FR-005-06** Save Clipboard. Reads the general pasteboard now and runs capture gates 2 to 5 and FR-001-17 on it regardless of capture mode (so it also works while Paused). In Curated mode it commits the held change (FR-001-19). In Active mode a clip already captured is deduplicated (FR-001-15) and counts as saved. Success shows the HUD `shortcuts.saved`; a rejected payload (transient or auto-generated, concealed with empty or whitespace-only plain text or no secure vault, ignored, empty, over limit) shows the relevant `CAP-*` code as a HUD. Content marked Transient or AutoGenerated is never saved. Content marked Concealed is saved as a secure item (FRD-001 FR-001-25: encrypted, masked, re-copy needs the owner to authenticate) with the same success HUD, because the gates are the ones a poll runs (FR-001-04 gate 3).
- **FR-005-07** Toggle Shelf. Calls the Shelf's show and hide (FRD-006). If the Shelf is disabled in Settings the hotkey is unregistered.

**Triggers: definition**
- **FR-005-08** Trigger grammar (single definition). A trigger is a case-insensitive string: first character an ASCII punctuation or symbol character (code points U+0021 to U+002F, U+003A to U+0040, U+005B to U+0060, U+007B to U+007E); then 1 to 23 characters, each an ASCII letter, digit, hyphen or underscore. Total length is 2 to 24. Anything else (spaces, control characters, non-ASCII, a letter or digit first) → `TRG-VAL-001`. Triggers are compared case-insensitively, so `;Sig` and `;sig` collide; a duplicate of another item's trigger → `TRG-VAL-002`. A trigger may be a prefix of another (`;s` and `;sig`): both are valid, because expansion requires the whole typed word to equal the trigger (FR-005-12).
- **FR-005-09** Assignment. The shortcut-and-trigger editor (⌘K on the selected item, context menu "Shortcut and Trigger...") shows a shortcut recorder field and, for text-bearing kinds only (`text`, `richText`, `link`, `color`, `phone`, `email`), a trigger field. Image, screenshot, file, folder and bundle items are not offered a trigger. An item has at most one hotkey and one trigger. The recorder field is the one shared control (the Settings Shortcuts rows use it too, FRD-008 FR-008-05): the chord appears as keycaps (⌃ ⌥ ⇧ ⌘ and the key), clicking the field records, an empty field shows "Record Shortcut" as its placeholder, and a clear control sits inside the field while a chord is set (a button with the tooltip and VoiceOver label "Clear Shortcut", `ui.settings.shortcutClear`). The recorder, the trigger field and the Add Clip editor use the one field look (the text-field surface with a 1 pt control-edge border, an accent ring while active), as does the Library search field (FRD-003 FR-003-04). The editor lays out as a two-column aligned grid (labels in one column, fields and their help text in the other). Text typed in the trigger field shows in the primary text colour; placeholder styling is for the empty field only. The variables reference (`ui.settings.editorVariablesHelp`) is not shown inline: a (?) button beside the trigger field (tooltip and VoiceOver label "Trigger Variables", `ui.settings.editorVariablesHelpButton`) opens it in a popover, so the form keeps one line of help under the field. The window title is "Edit Shortcut" (`ui.settings.editorWindow`). The clip being edited is named in a subtitle line at the top of the form, in secondary colour, on one line and cut in the middle when long; the name is the first non-empty line of its text (cut at 40 characters), else its first file's name, else its kind. The trigger help under the field is one short line: "Type it anywhere, then Space, Tab or Return." (`ui.settings.editorTriggerHelp`). The recorder field and the trigger field are the same height (28 pt) and use corner radii from the DESIGN token scale. Save is the default button (Return) and Cancel answers Esc. Validation errors are inline and block saving; `TRG-VAL-005` is a warning and does not block saving. Clearing a field removes the binding. A secure item (FRD-001 FR-001-25) can carry neither, so the editor does not open for it: ⌘K does nothing on a secure item and the context menu has no "Shortcut and Trigger..." row for it. The editor also opens for exactly one item: with several items selected ⌘K does nothing and the menu has no row. Both come from one rule (the Library reads it once for the key and the menu; the editor's own `TRG-VAL-006` refusal, FR-005-23, remains the backstop if one is opened some other way). Items with a hotkey or trigger show a badge in the Library (FRD-003).

**Triggers: activation and detection**
- **FR-005-10** Activation. The typed-trigger event tap exists only while all of these hold: (a) `triggers.enabled` is on (default on); (b) at least one item has a trigger; (c) Accessibility is granted (`AXIsProcessTrusted()`) and Input Monitoring is granted (`CGPreflightListenEventAccess()`). With no trigger defined, no tap is installed and no keystroke is observed. If (a) and (b) hold but a permission is missing, triggers are inert, no tap is installed, and the missing permission is reported with `SET-PRM-001` or `SET-PRM-002` (surfaced per FRD-000 and in the FRD-008 permission flow). The permission prompt is requested only when the user first saves a trigger or turns triggers on, never at launch. Hotkeys (FR-005-01 to -07) never depend on Input Monitoring. Refinements: the excluded-apps list is read from the `triggers.excludedApps` setting and kept current while running. The decision is re-evaluated after every item change, setting change and watchdog tick, and a missing permission is reported once per change, not on every tick. When a reported permission is granted (or triggers are turned off, or the last trigger is removed), its Notice is cleared in that same pass, so the menu-bar warning dot does not outlive the problem.
- **FR-005-11** Typed-word buffer. The tap is an active (default) session event tap on key-down, key-up, left, right and other mouse-down events, running on its own thread (never the main thread). It keeps one in-memory buffer holding the characters of the current word. Rules: a printable character with no modifier other than ⇧ and Caps Lock appends to the buffer (the character is read from the event with `CGEventKeyboardGetUnicodeString`, so any keyboard layout works); Backspace removes the last character; "character" here and in the 24-character limit means one user-perceived character, and the buffer's length is read from the buffer itself, never from a separate count; a character that is not ASCII (an accent or combining mark, a letter of another script such as Thai, an emoji, or a character that Unicode would normalise to an ASCII one, such as the Greek question mark U+037E, which is never read as `;`) kills the word: it is "dead" until the next boundary or reset, and Backspacing the character away does not bring the word back (text fields differ in how much one Backspace deletes after such input, a single mark or a whole character, so the word's true contents are unknown; a trigger is always ASCII (FR-005-08), so such a word could never match anyway); when a Backspace arrives on an empty buffer, the buffer would exceed 24 characters, or (in an excluded application, or with no identifiable application) the word stops being the start of any trigger (FR-005-20), the word is likewise "dead" until the next boundary or reset. The buffer is cleared, and a dead word becomes live again, by: a boundary key (FR-005-12), Esc, arrow keys, Home, End, Page Up and Down, function keys, Forward Delete, any other key that types no printable character, any chord with ⌘, ⌃ or ⌥, any mouse-down, a change of frontmost application, 5 seconds without a key event, and events from Flotsam itself (FR-005-13). Auto-repeat key events append like ordinary ones. The buffer lives only in memory (FR-005-20).
- **FR-005-12** Matching and boundary keys. The boundary keys are Space, Tab, Return and keypad Enter, pressed with no modifier except Caps Lock. A match occurs when a boundary key arrives, the word is not dead, and the buffer, compared case-insensitively, equals the trigger of exactly one item. On a match, and only if no suppression applies (FR-005-13), the tap swallows that key-down (returns no event) its matching key-up and any auto-repeat key-downs of the held boundary key, and starts the expansion (FR-005-14). The boundary key is consumed: it is not inserted after the expansion. When no match occurs the boundary key passes through untouched and the buffer is cleared. A boundary key pressed with ⇧ is not a boundary key: it passes through and ends the word without a match. Lookup uses an in-memory snapshot (trigger to item id) that is rebuilt on any trigger change; the tap callback never reads the database, the disk or the pasteboard.
- **FR-005-13** Suppression. Expansion does not happen, the boundary key passes through untouched, the buffer is cleared, and the outcome is logged as an Info code only, when: (a) Secure Event Input is enabled (`IsSecureEventInputEnabled()`; `TRG-POL-001`), including password fields and many remote and terminal contexts; (b) the frontmost application's bundle identifier is in `triggers.excludedApps` (`TRG-POL-002`); (c) the current keyboard input source is an input method rather than a keyboard layout (for example Japanese, Chinese or Korean composition), detected with `TISCopyCurrentKeyboardInputSource`; (d) the event carries Flotsam's marker (below); (e) the frontmost application is unknown or has no bundle identifier, because the exclusion list cannot be checked (fail closed; nothing is logged; the word buffer is limited as in an excluded application, FR-005-20). Flotsam's own posted events (backspaces, ⌘V, restored text, re-posted boundary keys) carry a fixed value in `eventSourceUserData` and the tap ignores any event carrying it. Default `triggers.excludedApps` (this FRD owns the default; FRD-008 shows and edits the list): `com.apple.Terminal`, `com.googlecode.iterm2`, `net.kovidgoyal.kitty`, `com.mitchellh.ghostty`, `io.alacritty`, `dev.warp.Warp-Stable`, `co.zeit.hyper`, `com.microsoft.rdc.macos`, `com.apple.ScreenSharing`, `com.parallels.desktop.console`, `com.vmware.fusion`. Flotsam's own windows are always excluded and not editable.

**Triggers: expansion**
- **FR-005-14** Expansion sequence. After a match the sequence runs off the tap thread: (1) load the item and, for text-bearing kinds, expand variables (FR-005-17); (2) check again that the frontmost application is unchanged and not excluded, Secure Event Input is still off and Accessibility is still granted, otherwise abort per FR-005-15; (3) snapshot the current pasteboard for restoration (FR-005-16); (4) write the item to the pasteboard with own-write markers (FRD-001 FR-001-03), full fidelity (rich representations kept, FR-005-18); (5) post N Backspace key events (key code 51, down then up), where N is the trigger length in characters, to delete what was typed; (6) post ⌘V per the FRD-003 FR-003-15 procedure (settle delay, target check); (7) increment `pasteCount` and set `lastUsedAt`; (8) restore the previous pasteboard (FR-005-16). Steps 5 and 6 are posted back to back with no more than 10 ms between events other than the FR-003-15 settle delay. Every key post of the expansion (the step 5 Backspaces, the step 6 ⌘V, and the FR-005-15 boundary-key and trigger-text re-posts) is addressed to the process the trigger was typed into, never to the session event tap, so a focus change after the step 2 check cannot send keystrokes to another application. Immediately before each post the target must still be frontmost and still running; otherwise nothing is posted for that call. A step 5 refusal takes the FR-005-15 steps 1 to 4 path.
- **FR-005-15** Failure handling. If any of steps 1 to 4 fails, nothing has been typed or deleted: the swallowed boundary key is re-posted (carrying the marker) so the application receives exactly what the user typed, and `TRG-OS-002` shows a HUD. If step 5 or 6 fails after backspaces were posted, the trigger text is re-posted as a Unicode string event, followed by the boundary key, and `TRG-OS-002` shows a HUD; restoring the text is best effort and the error message promises only that Flotsam tried. A missing Accessibility permission found at step 2 aborts as step 1 to 4 failures do and reports `SET-PRM-001`. Failures are logged by code only (FR-000-10). Refinements: (a) a failure at step 4 (pasteboard write) or a failed Backspace post at step 5 deletes nothing, so it takes the steps 1 to 4 path; Backspace events are all created before any is posted, so a failed post means none was. (b) The shown error is always `TRG-OS-002`, with the cause code in its log context; the text is never logged. (c) The boundary key and the typed text are re-posted only if the application that was frontmost at the match still is; if the user has moved on, nothing is posted (the key belonged to another app) and the HUD still shows, and the posting adapter enforces the same check at post time (FR-005-14). (d) A step 2 abort because Secure Event Input is on or the app is now excluded is a suppression, not a failure: nothing is shown, `TRG-POL-001` or `TRG-POL-002` is logged at Info, and the boundary key is re-posted. (e) On any failure the previous clipboard is not restored; the item stays on the pasteboard, as `LIB-OS-001` leaves it. (f) The pasteboard snapshot (step 3) is taken before variables are expanded because `{clipboard}` is that snapshot's plain text; no outcome depends on the order of steps 1 to 4.
- **FR-005-16** Clipboard preservation. Expansion (and item-hotkey paste) must not leave the user's previous clipboard replaced. Before writing, the general pasteboard's items and all their types are copied into memory; 300 ms after ⌘V is posted, if the pasteboard's `changeCount` equals the value after Flotsam's write (nobody else copied meanwhile), the copy is written back with own-write markers. If anything else changed the pasteboard, no restore is done. Snapshots over 32 MiB are not held and the previous clipboard is not restored (the size is checked once the copy is read, so it is never persisted); the history entry for that content already exists unless it was ignored; a concealed copy's entry is a secure item (FRD-001 FR-001-25), which exists the same way. A pasteboard carrying the Concealed or Transient marker is never read, held or restored: its type list is checked first, `{clipboard}` (FR-005-17) is empty, and the clipboard is left as the expansion's write leaves it. The snapshot is flat (type identifier to bytes), so a multi-item clipboard (for example several copied files) is restored as one item holding the first representation of each type; single-item content round-trips in full. The snapshot is held in memory only, never written to disk or logged, and is discarded after the restore or abort. Library Return, ⌥Return and ⇧Return paste (FRD-003) do not restore: the user explicitly put that item on the clipboard.
- **FR-005-17** Variables (single definition). Variables apply to text-bearing items when pasted by a trigger or an item hotkey; they do not apply to Library paste, Copy, previews or Shelf drags (those give the stored text literally). Syntax: `{name}` or `{name:format}`. Names: `date`, `time`, `clipboard`. `{date}` is the current date in the user's locale (medium style, for example "Nov 16, 2026"). `{time}` is the current time in the user's locale (short style, for example "2:05 PM"). `{date:FORMAT}` and `{time:FORMAT}` take a Unicode date pattern (for example `{date:yyyy-MM-dd}`, `{time:HH:mm}`) of 1 to 32 characters limited to ASCII letters, digits, space and `- / : , . '`; any other format → treated as unknown. `{clipboard}` is the plain text of the pasteboard at the moment of expansion step 3, or empty text if it has none (or if pasteboard privacy blocks the read); `{clipboard:...}` is unknown. Values are evaluated at expansion time in the current calendar and time zone. A variable inside an inserted value (for example a clipboard that itself contains `{date}`) is not expanded again. Unknown names or invalid formats are left unchanged as plain text and shown with `TRG-VAL-005` at save time. To write a variable literally, double the braces around a known name: `{{date}}` pastes `{date}`; other double braces (for example Go or Jinja templates) are left unchanged. The expanded text is limited to the text ceiling (FRD-007 FR-007-06); beyond it the expansion is truncated at the limit. No arithmetic, offsets, cursor markers, fill-ins or scripting exist (A2).
- **FR-005-18** Rich text keeps links. For `richText` items, variable expansion edits the attributed string in place so that run attributes (fonts, colours, links, paragraph styles) are kept; a variable inside a link's text is replaced within that link. RTF, HTML and plain representations are all written (FR-005-14 step 4) and the receiving app chooses. Plain-text items write plain text only. Links (`link` kind) paste as their URL text, with the `public.url` representation when stored.

**Health, privacy, performance, lifecycle**
- **FR-005-19** Tap health. If the tap callback receives `tapDisabledByTimeout` or `tapDisabledByUserInput`, the tap is re-enabled immediately, the buffer is cleared, and `TRG-OS-003` is added to Notices (throttled per FR-000-08). A 5-second watchdog (every 10th tick of the shared poll timer, ADR-0004; it adds no timer of its own, and it keeps its 5 seconds while capture is Paused, when the shared timer slows to 5 s, FR-001-19) checks `CGEvent.tapIsEnabled` and re-enables a tap that was disabled without a callback. If the tap is disabled three times within 60 seconds, it is not re-enabled again until the user toggles triggers off and on or relaunches, and the menu-bar icon warning dot stays set. Granting or revoking permissions while running installs or removes the tap within 5 seconds (checked by the same watchdog). Waking from sleep and fast user switching away and back reset the buffer and re-verify the tap. Refinements: while latched the tap is uninstalled, not merely left disabled. A disablement found by the watchdog counts toward the three-in-60-seconds limit exactly as a callback one does (and also reports `TRG-OS-003`). A re-enable that fails is replaced by a fresh install. If the system refuses an install, the failure is reported once per change of cause and retried at every watchdog tick; its Notice is cleared when an install succeeds.
- **FR-005-20** Keystroke privacy. The tap reads key events only to maintain the word buffer. Characters, the buffer, the matched word on a non-match, and the contents of any application are never persisted, logged, put in diagnostics, in a signpost or in an error context (FR-000-10), and never sent anywhere (A4). The buffer holds at most 24 characters and is cleared by every rule in FR-005-11. In an excluded application (FR-005-13 b, Flotsam's own windows included), and when the frontmost application is unknown or has no bundle identifier (FR-005-13 e, which fails closed the same way), it holds a word only while that word, compared case-insensitively, is the start of some trigger or a whole trigger; at the first character that makes it neither, the buffer is emptied and the word is dead until the next boundary (Backspace does not revive it), so ordinary typing there holds nothing. A whole trigger typed in an excluded application is still held to its boundary key and logged as `TRG-POL-002` without expanding (with an unknown application it is held the same way and suppressed without a log entry, FR-005-13 e); a trigger typed after a mistyped character in the same word is not logged, because the mistyped word was already dropped. The prefix check is one set lookup on the tap thread (FR-005-21). Every boundary key empties it, whether the word matched, was suppressed or matched nothing; the match is decided from the word the boundary key ended, which is moved out of the buffer first, so expansion is unaffected. A change of frontmost application empties it at the next key event on the tap thread (the signal is raised at once; the clear happens when the next event arrives). Logging records only the code of an outcome (matched and expanded, `TRG-POL-001`, `TRG-POL-002`, `TRG-OS-002`, `TRG-OS-003`). The tap adds no key observation when disabled or inert (FR-005-10).
- **FR-005-21** Performance. The tap callback (append, reset or match decision) takes at most 1 ms at p99 and never blocks on I/O, a lock held by another thread for more than a few microseconds, or the main thread. From the boundary key to ⌘V posted: p95 ≤ 150 ms for a text item up to 10 KB (`trigger.expand` signpost). Item hotkey to ⌘V posted: p95 ≤ 150 ms (`paste.back` signpost). Registering 100 item hotkeys at launch adds at most 50 ms to launch. Typing latency with the tap installed does not rise by a user-visible amount: the tap adds at most 1 ms per key event (measured as FR-005-21 callback time).
- **FR-005-22** Lifecycle links. Deleting an item (FRD-004 FR-004-09) unregisters its hotkey and removes its trigger from the snapshot immediately and in the same transaction. Editing an item's text (FRD-004 FR-004-07) takes effect at the next expansion. Ungroup (FRD-004 FR-004-11) does not carry hotkeys or triggers. Clear history (FRD-007 FR-007-11) keeps items with a hotkey or trigger (FRD-007 FR-007-10). A trigger or hotkey on an item exempts it from retention while the binding exists.
- **FR-005-23** Secure items are never expanded. A secure item (FRD-001 FR-001-25) is refused as a hotkey or typed-trigger payload with `TRG-VAL-006` before anything is revealed: no authentication prompt appears, nothing is written to the pasteboard and nothing is pasted, so a password is never decrypted by a keystroke it could not be shown for, and never run through variable expansion. It can never become a `{clipboard}` value either: Flotsam's own re-copy of a secure item carries `ConcealedType` (FRD-003 FR-003-23), and a Concealed pasteboard is read as an empty string (FR-005-16).

## 4. Data Requirements
- Item fields (schema in FRD-007): `hotkey` (key code, modifier flags; null when none), `trigger` (string; null when none). Uniqueness of `trigger` (case-insensitive) and `hotkey` is enforced at validation and by the database (unique indexes).
- Settings (registry in FRD-008): `shortcuts.openLibrary`, `shortcuts.saveClipboard`, `shortcuts.addClip`, `shortcuts.toggleShelf`, `triggers.enabled` (bool, default true), `triggers.excludedApps` (bundle identifiers; default list in FR-005-13).
- In memory only: the trigger snapshot, the word buffer, the pasteboard restore snapshot.
- Constants (one home, here): boundary keys; word-idle timeout 5 s; buffer limit 24; restore delay 300 ms; restore snapshot cap 32 MiB; watchdog interval 5 s; re-enable limit 3 in 60 s. The marker value for Flotsam's own events is one named constant.

## 5. Business Rules
- A trigger matches only a whole typed word that begins at a word start; `foo;sig` never expands.
- The boundary key that completes a trigger is consumed by the expansion; keys that complete nothing are never touched.
- Typed triggers never act under Secure Event Input, in excluded apps, or while an input method is composing.
- Variables expand only for triggers and item hotkeys.
- The user's clipboard is put back after an expansion if nobody else changed it.
- Flotsam never installs a keyboard tap when no trigger exists.
- Hotkeys: only chords with ⌘ or ⌃, never reserved or system-owned ones.

## 7. Acceptance Criteria
- **AC-005-01** (FR-005-01,03) Given a fresh install, then `openLibrary` is registered and no other global hotkey is; pressing it from another app toggles the Library; changing it rebinds immediately, and clearing it is refused.
- **AC-005-02** (FR-005-02) Given each of ⌥A, ⌥⇧A, ⇧A, ⌘Q, ⌘C, ⌘Space, ⌃Space and an enabled symbolic hotkey chord, then each is rejected with `TRG-VAL-003`; ⌃⌥A, ⌘⇧9 and ⌃⌘F5 are accepted; a chord already bound to another item is rejected with `TRG-VAL-004`.
- **AC-005-03** (FR-005-03) Given the OS refuses a registration (simulated), then `TRG-OS-001` shows, the binding stays saved with a warning badge, other hotkeys still work, and the registration is retried at relaunch.
- **AC-005-04** (FR-005-04) Given the recorder is recording, then pressing a registered Flotsam hotkey does not fire its action; after Esc all hotkeys work again; Delete clears a clearable binding; given a rejected chord (⌘C) showed its inline error, when ⌃⌥B is then recorded, the recorder stops and no inline error remains (also after Esc).
- **AC-005-05** (FR-005-05,16) Given an item with a hotkey and a text field focused in another app, when the hotkey is pressed, then the item's text is pasted at the cursor, no Flotsam window appears, and the previous clipboard contents are back on the pasteboard within 600 ms of the paste; with Accessibility off, the item is placed on the clipboard only and `SET-PRM-001` shows.
- **AC-005-06** (FR-005-06) Given Curated mode and text copied, when Save Clipboard runs, then one item exists with a HUD; given Paused mode it also saves; given Concealed content it saves one secure item (masked, no plain text stored) and shows `shortcuts.saved`; given Transient content it saves nothing and shows the matching `CAP-*` HUD; given content already stored it bumps `copyCount` instead of adding a row.
- **AC-005-07** (FR-005-08) Given the inputs `;sig`, `;Sig` (duplicate), `sig`, `;`, `; sig`, `;é`, `;` followed by 23 letters (24 characters total, accepted) and by 24 letters (25 total, rejected), then the grammar accepts and rejects exactly as specified, using `TRG-VAL-001` and `TRG-VAL-002`.
- **AC-005-08** (FR-005-09) Given an image item, then the editor offers a hotkey but no trigger field; a text item offers both; clearing a trigger removes it from expansion immediately.
- **AC-005-08a** (FR-005-09) Given a secure item selected in the Library, then ⌘K opens nothing (and the Library stays), and its context menu has no "Shortcut and Trigger..." row; given several items selected, then ⌘K opens nothing and the context menu has no such row; given one ordinary text item, both open the editor.
- **AC-005-09** (FR-005-10) Given no item has a trigger, then no event tap exists (verified by listing the process's taps) and the permission prompt has not been requested; given a trigger exists and Input Monitoring is off, then no tap is installed and `SET-PRM-002` is reported; granting the permission installs the tap within 5 seconds and clears the `SET-PRM-002` Notice (the same holds for `SET-PRM-001`; with both missing, granting one clears only its own).
- **AC-005-10** (FR-005-11,12) Given trigger `;sig` and a TextEdit document, when `;sig` then Space is typed, then the item text replaces `;sig` and no space remains; when `x;sig` then Space is typed, nothing expands and the space is inserted; `;si` then Space does not expand; `;sig` then Backspace, `g`, Space expands; `;sig`, a mouse click, then Space does not expand; `;sig` then Tab and then Return each expand when they are the boundary; given trigger `;ab`, when `;ab`, then a non-ASCII character (for example the Thai ก followed by a Thai mark), then Backspace once or more, then Space is typed, nothing expands and nothing is deleted (the word stays dead even when only ASCII is left in the field), and the next word `;ab` then Space, typed after that boundary, expands normally.
- **AC-005-11** (FR-005-12) Given triggers `;s` and `;sig`, then typing `;s` Space expands the first, `;sig` Space expands the second, and neither fires early at the shorter prefix.
- **AC-005-12** (FR-005-13) Given a Terminal window frontmost (default exclusion), then `;sig` Return passes through unchanged and `TRG-POL-002` is logged with no HUD; given Secure Event Input enabled by a password field, then nothing expands and `TRG-POL-001` is logged; given a Japanese input method composing, nothing expands.
- **AC-005-13** (FR-005-14) Given a chat box where Return sends a message, then `;sig` Return expands the text without sending the message, the trigger text is not left behind, and `lastUsedAt` and `pasteCount` are bumped.
- **AC-005-14** (FR-005-15) Given an injected failure in step 4 (pasteboard write), then the app shows `;sig` and the boundary key as typed and a HUD with `TRG-OS-002`; given an injected failure in step 6, then the trigger text and boundary key are re-posted and the HUD shows.
- **AC-005-15** (FR-005-16) Given an image on the clipboard, when a trigger expands, then the image is back within 600 ms; given another app copies during the 300 ms window, the clipboard is left as that app set it; given a 40 MiB clipboard, it is not restored and the history already holds that clip.
- **AC-005-16** (FR-005-17) Given `{date:yyyy-MM-dd}` then the pasted text is today's date in that form; `{time}` is the short locale time; `{clipboard}` is the plain text copied before the expansion (empty when none); `{foo}` and `{date:@@}` stay as typed and show `TRG-VAL-005` at save; `{{date}}` pastes `{date}`; `{{ .Name }}` is unchanged; a clipboard holding `{date}` is inserted without being expanded again; Library Return on the same item pastes it with `{date}` unexpanded.
- **AC-005-17** (FR-005-18) Given a rich-text item whose text contains a hyperlink, then after a trigger expansion into a rich-text-capable app the link is still a link; a `{date}` inside the link's text is replaced inside the link.
- **AC-005-18** (FR-005-19) Given the tap is disabled (simulated `tapDisabledByTimeout`), then it is re-enabled, the buffer is cleared and a Notice `TRG-OS-003` appears; given three disablements within 60 seconds, then it stays disabled, the warning dot is set, and toggling triggers off and on restores it.
- **AC-005-19** (FR-005-20) Given a debug run that types a marker word and then a trigger, when the unified log, diagnostics report and signposts are searched, then neither the marker word nor any typed text is present; only outcome codes appear.
- **AC-005-20** (FR-005-21) Given 1,000 scripted key events with 100 triggers defined, then the tap callback p99 is ≤ 1 ms; over 50 expansions of a 10 KB item, boundary key to ⌘V posted is p95 ≤ 150 ms.
- **AC-005-21** (FR-005-22) Given an item with a hotkey and trigger is deleted, then the hotkey no longer fires and the trigger no longer expands, with no relaunch; Clear history keeps it; Ungroup does not copy the bindings.
- **AC-005-22** (FR-005-13) Given the Flotsam-posted backspaces and ⌘V from an expansion, then they do not enter the word buffer or start another expansion, including when the expanded text itself begins with a trigger.
- **AC-005-23** (FR-005-23) Given a secure item whose hotkey or trigger reaches expansion (for example one set before it was captured as secure), then `TRG-VAL-006` is reported, no prompt appears, the pasteboard is unchanged and nothing is pasted; given a secure item was just copied by Flotsam, then `{clipboard}` in the next expansion is empty.

## 9. Assumptions and open items (flagged for Friday)
1. Default chord. `⌃⌘V` is provisional. It must be checked in a spike against macOS 26 system shortcuts and common apps (Finder, Safari, Slack, Xcode, VS Code, Terminal) before it is final; `openLibrary` is the only default so a collision costs one chord, not several.
2. macOS 15 and later (so every supported version) refuse `RegisterEventHotKey` for ⌥ and ⌥⇧ only combinations (FR-005-02a). Believed from platform behaviour and not yet re-verified on macOS 26; the rule is also safe if the restriction is lifted.
3. Event-tap permissions. An active keyboard tap is assumed to need Accessibility and, to be reliable, Input Monitoring; Flotsam requires both before installing it (FR-005-10). Verify which prompts macOS 26 shows.
4. Consuming the boundary key (FR-005-12) is a product choice: it avoids a stray Return sending a chat message with the trigger text. The cost is that `;sig` Space leaves no trailing space. If dogfooding dislikes it, change to re-posting Space and Tab after the paste while still consuming Return; this would be an FRD change.
5. Variables apply to triggers and item hotkeys only (FR-005-17), so Library paste is always literal.
6. Clipboard restore (FR-005-16) holds a copy of the user's previous clipboard in memory for about 300 ms. Concealed and Transient content (a copied password, a one-time code) is never read or held, so it is not restored: after an expansion the clipboard holds the expanded item instead of the password. This is the privacy-first choice (Ryan's brief: never act on concealed or transient content); the alternative is holding it in memory for 300 ms. It is never persisted either way. A multi-item clipboard restores as one item (FR-005-16).
7. Default excluded apps (FR-005-13) are terminals and remote-desktop or VM clients. Browsers and IDEs are not excluded by default; S4's falsifier names them, so this list is the first thing to adjust if misfires occur.

## 10. Out of Scope
Scripts, forms, nested snippets, fill-in fields, cursor placement markers, date arithmetic, conditional or looping content, team or shared libraries (A2). Triggers that expand without a boundary key, configurable boundary keys, triggers on non-text items. Per-item "paste as plain text" toggles. Syncing hotkeys or triggers (A1). Global hotkeys for in-panel actions. Chord sequences (two-step shortcuts). Any network access (A4).
