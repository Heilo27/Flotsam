# FRD-001 — Clipboard Capture

**Status:** Draft · 2026-11-16 · Constitution: [TRUTHS.md](../TRUTHS.md) · PRD: [PRD.md](../PRD.md) (feature F1) · Errors: [FRD-000](FRD-000-ErrorSystem.md)
**Owns:** pasteboard polling, which pasteboard types are honoured, item classification (`ItemKind`), typed-text detection, source-app attribution, the dedupe rule, bundle semantics, what capture skips.
**Does not own:** storage, limits and the ingest pipeline ([FRD-007](FRD-007-RetentionStorage.md)); the ignored-apps list and its defaults ([FRD-008](FRD-008-OnboardingSettings.md)); paste-back ([FRD-003](FRD-003-Library.md)).

## Truth Test
- Serves: P1 — every copy is in history within about a second, entirely on this Mac, so "yesterday's link" exists to be recalled.
- Supports: S1 — type detection (link, colour, phone, email, file, folder, image) is what lets users recall by what a clip was; S2 — a multi-file copy is stored as one bundle.
- Violates: none (capture reads only the local pasteboard; secret-marked copies are skipped, per A4's spirit and CLAUDE.md).
- Verdict: KEEP

## 1. Purpose
Watch the macOS general pasteboard, decide what is worth keeping, classify it, and hand it to the ingest pipeline, invisibly and cheaply.

## 2. User Stories
- As a keyboard-first user, everything I copy is in the Library by the time I open it, with no setup.
- As a security-conscious user, a password-manager copy lands in history only as an encrypted, masked item that needs my password or Touch ID to copy again, and I can ignore a manager entirely.
- As a designer, copying five files in Finder gives me one entry I can paste or drag as a unit.
- As a user, a link is a link and a hex colour is a colour, so I can filter for them later.

## 3. Functional Requirements

**Observation**
- **FR-001-01** Polling. A repeating timer fires every **0.5 s** with **0.1 s** tolerance, scheduled in `.common` run-loop modes so it keeps firing while menus are tracked. Each tick compares `NSPasteboard.general.changeCount` with the last processed value; equal → return with no other work. There is no other pasteboard read between changes, with one exception: a copy is not atomic (the pasteboard bumps `changeCount` when it is cleared and fills without a second bump), so a change whose read returns no type data is watched: it is read again on every following tick until it fills, a newer `changeCount` arrives, or **10 s** have passed since the change first appeared (the empty-change watch limit, one constant). Data that lands inside the watch is captured as that copy, exactly once. A read at 9.9 s still stores; at 10.0 s the watch has ended, nothing is stored and the change counts as an empty change (`CAP-VAL-001`, and toward FR-001-18 b).
- **FR-001-02** Immediate polls. Capture runs one synchronous check (`captureNow`) (a) when the Library or Shelf is about to be shown (FRD-003, FRD-006 call it before first render), (b) on `NSWorkspace.didWakeNotification`, (c) on `NSApplication.didBecomeActiveNotification`, and (d) on launch. `captureNow` is idempotent and returns after the item is queued, not after it is persisted.
- **FR-001-03** Own-write markers. Every pasteboard write by Flotsam (paste-back, trigger expansion, Copy Diagnostics, copy-to-clipboard fallbacks) adds the types `org.nspasteboard.AutoGeneratedType` and `com.flotsam.own-write` (empty data) and records the `changeCount` returned by the write. A change whose `changeCount` equals a recorded own-write value, or whose types include `com.flotsam.own-write`, is skipped with `CAP-POL-004`.
- **FR-001-04** Policy gate. On a changed `changeCount` the gates run in this order and stop at the first that rejects: (1) capture mode is Active, or Curated (FRD-007 FR-007-12; Paused or Curated-without-save → `CAP-POL-003`); (2) own-write (FR-001-03); (3) either of `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` present → `CAP-POL-001` (presence alone rejects, regardless of data); `org.nspasteboard.ConcealedType` present → a secure item (FR-001-25), or `CAP-POL-001` when its plain text is empty or only whitespace or the secure vault is unavailable; (4) resolved source app (FR-001-13) is in the ignored list → `CAP-POL-002`; (5) the payload yields at least one honoured representation (FR-001-05) → else `CAP-VAL-001`. Gate 1 does not read pasteboard data; gates 2 to 4 read type identifiers and the source marker only; payload bytes are read only after all gates pass.
- **FR-001-21** Secure Event Input has no effect on capture. Capture continues while `IsSecureEventInputEnabled()` is true; secure input suspends typed triggers only (FRD-005).

**Which pasteboard types**
- **FR-001-05** Honoured types: `public.utf8-plain-text` (also read via `NSPasteboard.PasteboardType.string`), `public.rtf`, `public.html`, `public.png`, `public.tiff`, `public.jpeg` (fallback only when no PNG or TIFF), `public.file-url`, `public.url` (used only to confirm a link; the plain text is the stored value).
- **FR-001-06** Ignored types (never stored, never cause a capture by themselves): file promises (`com.apple.pasteboard.promised-file-url`, `com.apple.pasteboard.promised-file-content-type`, `com.apple.NSFilePromiseItemMetaData`), `com.apple.cocoa.pasteboard.color`, `com.adobe.pdf`, `public.url-name`, `com.apple.finder.node`, `com.apple.icns`, and any `dyn.*` or application-private identifier. A pasteboard containing only ignored types is `CAP-VAL-001`. File promises are unsupported in v1 (the file does not exist yet at copy time).
- **FR-001-07** Multiple pasteboard items. If the pasteboard holds more than one `NSPasteboardItem` and any carries `public.file-url`, all file URLs form one set (FR-001-12). Otherwise only the first pasteboard item is captured; the rest are ignored.

**Classification**
- **FR-001-08** `ItemKind` is the single closed enumeration: `text`, `richText`, `link`, `color`, `phone`, `email`, `image`, `file`, `folder`, `bundle`, `screenshot`. (`screenshot` is assigned only by FRD-002.) Precedence, first match wins: (1) one or more file URLs → `file`, `folder` or `bundle` (FR-001-12); image and text representations on the same pasteboard (Finder icons, file names) are discarded; (2) non-whitespace plain text present → a text-bearing kind (FR-001-09, FR-001-10), and any image representation on the same pasteboard is discarded (spreadsheet and presentation apps attach an image of the selection); (3) an honoured image representation and no non-whitespace plain text → `image`.
- **FR-001-09** Typed-text detection. Applied to the plain text after trimming leading and trailing whitespace and newlines, only when it has no internal newline. The whole trimmed string must match; partial matches never count. Evaluated in this order:
  - `link`: parses as a URL with scheme `http`, `https`, `ftp` or `ftps`, a non-empty host, and no whitespace; or `public.url` is present and its string equals the trimmed text.
  - `email`: matches `^[^\s@]+@[^\s@]+\.[^\s@]{2,}$` and is at most 254 characters.
  - `color`: `#RGB`, `#RGBA`, `#RRGGBB`, `#RRGGBBAA` (hex, case-insensitive), or `rgb(...)`, `rgba(...)`, `hsl(...)`, `hsla(...)` with numeric or percentage arguments. Named colours and `0x...` are not colours.
  - `phone`: contains only digits and `+ ( ) - . ` and space; at most one `+`, only as the first character; 7 to 15 digits; a string with no separator and no `+` qualifies only at 10 to 15 digits.
  - Anything else with plain text → `richText` if FR-001-10 applies, otherwise `text`.
- **FR-001-10** Rich text. If `public.rtf` or `public.html` is present, those representations are stored alongside the plain text. A typed kind (FR-001-09) still wins the classification but keeps the rich representations so paste-back stays faithful; otherwise the kind is `richText`. Paste-back writes every stored representation (FRD-003). If no plain text exists but RTF or HTML does, plain text is derived from it by stripping markup; if that is empty or whitespace-only → `CAP-VAL-001`.
- **FR-001-11** Images. Accepted representation priority: `public.png`, then `public.tiff`, then `public.jpeg`. The chosen bytes go to the image pipeline (FRD-007 FR-007-07), which stores PNG or JPEG as received and converts TIFF to lossless PNG. Pixel width and height are recorded at ingest. An undecodable image → `CAP-VAL-001`.
- **FR-001-12** Files, folders, bundles. File URLs are read in pasteboard order, standardised (`standardizedFileURL`; symbolic links are not resolved), and filtered to those that exist at capture time. None exist → `CAP-DAT-001`. Exactly one existing URL: a directory that is not a package → `folder`; anything else, including packages such as `.app` → `file`. Two or more → one `bundle` whose members keep pasteboard order and each member stores its path, a bookmark (so renames and moves can be followed), and whether it is a directory. Files are stored by reference; their contents are never copied into Flotsam's store. More than 500 members → keep the first 500 and raise `CAP-LIM-003` with the real count; capture passes every member through untrimmed and the one ceiling and its one raise live in ingest (FR-007-06), so `contentKey` (FR-001-15) covers every copied path. Capture creates bookmarks only for the first 500 members; later members are kept by path so ingest reports the true count. By default a bundle is always one item: capture does not split it, and ungrouping is a user action (FRD-004). The one exception is the setting "Group copied files into a bundle" (`capture.autoBundle`, default on, FRD-008 FR-008-01): when it is off, a copy of two or more files is stored as one `file` or `folder` item per URL, each classified and deduped as a single-file copy, with `lastCopiedAt` of the nth URL (zero-based) set n milliseconds before the first so Recent shows them in pasteboard order. The setting is read at each copy, so a change applies to the next one. It applies to copies and Save Clipboard Now only: files dropped on the Shelf always form a bundle (FRD-006 FR-006-13), and a bundle can still be made by hand (FRD-004 FR-004-41).

**Attribution**
- **FR-001-13** Source app. Resolved as: the bundle identifier in `org.nspasteboard.source` when present and non-empty; otherwise the frontmost application's bundle identifier at the moment the change is detected; otherwise unknown (`CAP-OS-002`, shown as "Unknown"). The app's localized name is stored with the identifier. Icons are resolved at display time and never stored. The resolved source is evaluated against the ignored list (FR-001-04 gate 4) and stored on the item.
- **FR-001-14** Remote clipboard. A pasteboard carrying `com.apple.is-remote-clipboard` (Universal Clipboard from another device) is captured like any other; its source is recorded as the label "Another device" with no bundle identifier. It cannot be matched by the ignored-apps list. Concealed and transient markers are judged exactly as on any other copy (FR-001-04 gate 3): a transient or auto-generated marker rejects it; a concealed one is kept as a secure item (FR-001-25) whose source reads "Another device".

**Dedupe**
- **FR-001-15** Dedupe rule. Each capture computes a `contentKey` = `<class>:<SHA-256 hex>` where the class and the hashed bytes are: `text` (kinds text, richText, link, color, phone, email) = the exact UTF-8 bytes of the plain text as copied (no trimming, no case or Unicode normalisation); `image` = the raw bytes of the chosen image representation before any conversion; `files` (kinds file, folder, bundle) = the standardised paths in pasteboard order joined by U+0000. If any existing item has the same `contentKey` (anywhere in the library, any age, pinned or not), no new item is created. Instead the existing item's `lastCopiedAt` is set to now and `copyCount` incremented, so it moves to the top of Recent. Its id, kind, source app, tags, note, pin, shortcuts and stored representations are unchanged. Rich-text differences between copies of the same plain text are ignored. Editing a text item (FRD-004) recomputes its `contentKey`. The class prefix means a screenshot and an image with identical bytes also dedupe, keeping the original kind. Exception: a screenshot backfill import (FRD-002 FR-002-12) is not a copy event — a match leaves the existing item fully untouched (no `lastCopiedAt` or `copyCount` change).

**Limits, hand-off, resilience**
- **FR-001-16** Per-item ceilings are defined once, in FRD-007 FR-007-06. Capture behaviour on breach: plain text over the text ceiling → skip, `CAP-LIM-001`; rich representations over their ceiling → drop only those, keep plain text, `CAP-LIM-002`; image over the image ceiling → skip, `CAP-LIM-001`. The pasteboard itself is never modified, so the user's clipboard is unaffected.
- **FR-001-17** Hand-off. After the gates, capture builds an immutable `CapturedPayload` value (kind, representations, source, contentKey, timestamp) and passes it to the ingest pipeline (FRD-007 FR-007-05) on a background actor. The main thread never performs hashing, image conversion or database work. Capture has no persistence code of its own.
- **FR-001-18** Pasteboard privacy. Because every supported macOS (26 and later) gates programmatic pasteboard reads (the "Paste from Other Apps" setting, introduced in macOS 15.4; enforcement behaviour on macOS 26 is unverified, see Assumptions), capture is suspended and `CAP-PRM-001` raised when either (a) the system reports an access behaviour other than "allow", or (b) three consecutive `changeCount` increments is still empty when its watch ends (FR-001-01: at 10 s, or when a newer `changeCount` supersedes it). A copy whose content lands during the watch is not an empty change: it does not count and it resets the consecutive count. The consecutive count is therefore reached when the third watch ends, up to 10 s after the third copy. Trigger (a) is checked once at launch, before the first poll, through a port (`PasteboardAccessPort`) so it is testable. Capture retries on every `didBecomeActive` and every 60 s while suspended, and on the first successful read resumes and clears the `CAP-PRM-001` Notice and with it the menu-bar warning dot. The Notice clearing also restarts the `CAP-PRM-001` 60 s throttle (FR-000-08), so a second suspension within 60 s of a resume shows the Notice again. Trigger (b) counts `changeCount` increments only: reading the same count again (Save Clipboard pressed repeatedly on one unchanged empty pasteboard, FR-005-06) is not another empty change and never suspends capture. Onboarding (FRD-008) instructs the user to set Allow.
- **FR-001-19** Capture modes. Active, Paused and Curated are defined and persisted in FRD-007 FR-007-12. In Paused, capture does no pasteboard work: the 0.5 s poll stops and the shared timer (ADR-0004) slows to the coarsest interval the work still registered with it needs (5 s with the tap watchdog, FR-005-19, and the screenshot folder re-resolve, FR-002-02), which keep their 5 s and 30 s bounds across every pause and resume, including rapid cycling (the shared timer is re-created on each change, so work already due runs at once rather than waiting a full new interval); with none registered the timer is not scheduled. Resuming brings the 0.5 s tick back and runs one immediate check against a `changeCount` baseline read at the moment the mode changes (an on-demand check that lands just after the change uses that baseline too), so nothing copied while Paused is ever captured, not on resume and not later. Save Clipboard (FRD-005) still reads the pasteboard on demand, and the launch, wake and activation checks (FR-001-02) still run and capture nothing. In Curated, a change is held only as the "current clipboard" until the user invokes Save Clipboard (FRD-005); the saved payload then runs FR-001-04 gates 2 to 5 and FR-001-17.
- **FR-001-20** Performance. Idle (no panel open, 10,000 items) over 10 minutes with no copies: the whole app averages at most 0.2 % of one CPU core, at most 2.5 wake-ups per second and a physical footprint (`phys_footprint`, as reported by `footprint`) of at most 60 MB (truth S5); the pasteboard poll is the only recurring wake-up source, so any other periodic work shares its tick instead of adding a timer (the tap watchdog, every 10th tick, and the folder re-resolve, every 60th tick, run on it; ADR-0004 lists the few other timers and their cost). Detection latency is at most 0.6 s after the pasteboard changes. Change to queryable item (persisted and returned by a Library query): p95 at most 250 ms for text up to 100 KB and at most 750 ms for an image up to 5 MiB, excluding the detection latency; thumbnails are generated afterwards and may arrive later. The physical footprint (`phys_footprint`) stays under 150 MB with 10,000 items and a panel open. Measured with the `capture.persist` signpost (FR-000-12).
- **FR-001-22** Read failure. If reading a payload throws or returns inconsistent data, the change is dropped with `CAP-OS-001` and the next tick proceeds normally; one bad read never stops the timer. A capture write that the disk or database refuses (`STO-DB-001`, `STO-IO-001` from the pipeline) surfaces as `CAP-IO-001` (the log record keeps the cause: the underlying system error when there is one, and always the refused `STO-*` code as its `code` context field, since a refusal from the disk-space or blob-file check carries no underlying error); other pipeline failures keep their `STO-*` or `CAP-*` code. The failed item is lost and the next copy is written normally.
- **FR-001-25** Secure items (a concealed copy). A copy carrying `org.nspasteboard.ConcealedType` is kept as a *secure item*: its plain text is sealed with AES-GCM under a key held in the Keychain and only the ciphertext (at most 64 KB) is stored; no plaintext, no other representation, no preview, no search entry and no log line holds the content. The Library, search and Shelf show the mask `••••••••` with the source app; search never matches the content. A secure item cannot be edited (`ORG-VAL-003`), cannot carry a hotkey or trigger (`TRG-VAL-006`, enforced by the database as well) and cannot be a trigger variable value. Delete, retention and Clear History remove the ciphertext with the row; Reconcile does not treat it as empty. If the key is missing the row reads "Unavailable" and is never an error at launch. Copying one back needs the owner to authenticate (`LIB-OS-002`, `LIB-DAT-002`; FRD-003). A concealed copy whose plain text cannot be read is handled like any other unreadable copy (FR-001-22, `CAP-OS-001`): nothing is stored and no plain text of it exists anywhere (not in the database, not in the log). A concealed copy whose plain text is empty or only whitespace is rejected with `CAP-POL-001` (a policy skip, not an error): nothing is stored, because a blank password is not worth sealing. Trade-off: a password manager's own auto-clear no longer limits exposure, because Flotsam keeps an encrypted copy until the item is deleted or expires.

## 4. Data Requirements
- Produces `CapturedPayload`: `kind: ItemKind`, `representations: [(type: UTI, bytes)]`, `files: [FileRef]?` (path, bookmark, isDirectory), `source: SourceApp?`, `contentKey: String`, `capturedAt: Date`, `isRemote: Bool`.
- Reads app state: capture mode and ignored-apps list (FRD-008 registry); writes nothing directly.
- In-memory only: last processed `changeCount`, recorded own-write counts (last 8), consecutive-empty-change counter, and the empty `changeCount` being watched with the time it first appeared (FR-001-01).

## 5. Business Rules
- Content never appears in logs (FR-000-10). Capture logs kind, byte size, outcome and code.
- Transient and auto-generated markers reject on presence, never on inspecting data. A concealed marker makes a secure item (FR-001-25): only its plain text is ever read.
- The 0.5 s poll can miss an intermediate value if two copies happen inside one tick; this is accepted and documented (the pasteboard holds only the latest value).
- Detection is deterministic and content-only; it never consults the network or the source app's claim of type.
- A copy is never deleted from the user's pasteboard by Flotsam.

## 6. Error States (all codes defined in FRD-000 §7)
| Situation | Code | Behaviour |
|---|---|---|
| macOS blocks pasteboard reads (at launch or after empty changes) | CAP-PRM-001 | capture suspended, Notice, retry; Notice clears on resume (FR-001-18) |
| Read failure (including a concealed copy whose plain text cannot be read: nothing is stored) | CAP-OS-001 | skip tick |
| Source app unresolvable | CAP-OS-002 | store as Unknown |
| Transient, auto-generated | CAP-POL-001 | skip |
| Concealed with empty or whitespace-only plain text, or no secure vault | CAP-POL-001 | skip (fails closed) |
| Ignored source app | CAP-POL-002 | skip |
| Paused or curated | CAP-POL-003 | skip |
| Own write | CAP-POL-004 | skip |
| Empty, whitespace-only, unsupported or undecodable | CAP-VAL-001 | skip |
| Copied files vanished | CAP-DAT-001 | skip |
| Item too large | CAP-LIM-001 | skip, Notice |
| Rich representation too large | CAP-LIM-002 | keep plain text |
| More than 500 files | CAP-LIM-003 | keep first 500, Notice |
| Disk or database refused the write | CAP-IO-001 (from `STO-DB-001` / `STO-IO-001`) | not stored, Notice |

## 7. Acceptance Criteria
- **AC-001-01** (FR-001-01) Given idle, then a profile over 10 minutes shows average CPU at most 0.2 % of one core, at most 2.5 wake-ups/s and a physical footprint of at most 60 MB (AC-001-16), and the timer interval is 0.5 s ± 0.1 s; given the Edit menu of any app is held open, a copy made by script is still detected.
- **AC-001-02** (FR-001-02,20) Given a script copies "X" then the Library hotkey is pressed within 50 ms, then "X" is the top item when the panel first renders.
- **AC-001-03** (FR-001-03) Given Flotsam pastes an item back, then no new item is created and the item's copy count is unchanged; log shows `CAP-POL-004`.
- **AC-001-04** (FR-001-04) Given a pasteboard written with `org.nspasteboard.TransientType` and text "secret-marker", then nothing is stored, `CAP-POL-001` is logged, and the marker is absent from logs; the same holds for `AutoGeneratedType`, and for `ConcealedType` when no secure vault is available.
- **AC-001-25** (FR-001-25) Given a pasteboard written with `org.nspasteboard.ConcealedType` and text "secret-marker", then one secure item is stored; the database file, its WAL and the log contain no occurrence of the marker; the row's primary line is the mask `••••••••` with its source app; searching for the marker finds nothing; and the item has no plain text, no other representation, no hotkey and no trigger; given the same pasteboard when its plain text cannot be read, then nothing is stored, `CAP-OS-001` is logged (not `CAP-POL-001`), and the marker is absent from logs; given the same pasteboard when its plain text is empty or only whitespace, then nothing is stored and `CAP-POL-001` is logged as a skip; given the same copy arriving as a remote clipboard (FR-001-14), then the same secure item is stored with the source "Another device".
- **AC-001-26** (FR-001-25) Given a secure item, then Edit is refused (`ORG-VAL-003`), a hotkey or trigger assignment is refused (`TRG-VAL-006`), no trigger variable can take its value, and Delete, retention and Clear History remove its ciphertext; Reconcile never deletes it for lacking plain text.
- **AC-001-27** (FR-001-25) Given a secure item whose Keychain key is missing, then the row reads "Unavailable" and nothing crashes.
- **AC-001-05** (FR-001-04) Given the source app is on the ignored list, when it copies text, then nothing is stored (`CAP-POL-002`); given Paused, nothing is stored (`CAP-POL-003`) and, after resume, a new copy is stored.
- **AC-001-06** (FR-001-05,06) Given a pasteboard with only a file promise, only `com.adobe.pdf` data, or only an app-private type, then nothing is stored and `CAP-VAL-001` is logged.
- **AC-001-07** (FR-001-09) Given the fixtures `https://example.com/a`, `a@b.co`, `#1A2b3C`, `rgba(10, 20, 30, 0.5)`, `+1 (415) 555-0100`, `4155550100`, `1234567`, `see https://example.com`, `www.example.com`, `rebeccapurple`, then they classify as link, email, color, color, phone, phone, text, text, text, text.
- **AC-001-08** (FR-001-08,10) Given a web-page selection with HTML and plain text, then kind is `richText` and both representations are stored; given an address-bar copy with `public.url`, then kind is `link`; given a spreadsheet range with text and TIFF, then kind is text-bearing and no image is stored.
- **AC-001-09** (FR-001-11) Given a PNG-only pasteboard and a TIFF-only pasteboard, then both become `image` items with width and height recorded, and the TIFF is stored as PNG.
- **AC-001-10** (FR-001-12) Given a Finder copy of 1 file, 1 folder, 1 `.app`, and 3 files, then the kinds are file, folder, file, bundle; the bundle has 3 members in selection order; deleting one member from disk afterward leaves the bundle intact.
- **AC-001-41** (FR-001-12) Given `capture.autoBundle` off and a Finder copy of 3 files, then 3 `file` items exist, listed in pasteboard order in Recent, and no bundle; given it is turned back on, the next copy of 3 files is one bundle; given it is off and 1 file is copied, one `file` item exists as always; given it is off, files dropped on the Shelf still form one bundle.
- **AC-001-11** (FR-001-12) Given 600 files copied, then the bundle has 500 members and `CAP-LIM-003` appears in Notices.
- **AC-001-12** (FR-001-13) Given a copy from a source that writes `org.nspasteboard.source`, then that bundle id is stored; given none, then the frontmost app is stored; given neither resolvable, then "Unknown" is stored and capture succeeds.
- **AC-001-13** (FR-001-15) Given "abc" is copied, then a tag is added to it, then "abc" is copied again, then there is still one item with the tag, `copyCount` is 2 and it is first in Recent; given "abc " (trailing space) and "ABC", then each creates a new item.
- **AC-001-14** (FR-001-16) Given a text copy over the ceiling, then nothing is stored, `CAP-LIM-001` is raised and the user's pasteboard still holds the text.
- **AC-001-15** (FR-001-18) Given reads are blocked by system policy, then after three empty changes (each still empty when its 10 s watch ends, FR-001-01) capture shows `CAP-PRM-001` and resumes within one tick after access is allowed.
- **AC-001-16** (FR-001-20) Given a scripted run of 200 copies (text up to 100 KB) and 20 images of 5 MiB, then p95 persist latency meets FR-001-20; and given a pre-seeded 10,000-item library with no panel open, then the app's physical footprint (`phys_footprint`, as reported by `footprint <pid>` on the release build) read once after the run has gone idle for at least 45 s is at most 60 MB (RSS is not the budget metric), and the physical footprint with a panel open stays under 150 MB.
- **AC-001-17** (FR-001-21) Given secure event input is enabled (password field focused), when text is copied from a non-ignored app, then it is captured.
- **AC-001-18** (FR-001-01, FR-001-18) Given a file copy whose pasteboard content lands after the clear, then the copy is captured, and three such copies in a row that each fill within the watch do not suspend capture or raise `CAP-PRM-001`.
- **AC-001-20** (FR-001-01) Given a copy whose content lands 1.5 s, 5 s or 9 s after the clear, then it is stored exactly once; the 9 s copy does not suspend capture.
- **AC-001-21** (FR-001-01) Given a copy whose content lands 12 s after the clear, then nothing is stored and `CAP-VAL-001` is logged.
- **AC-001-22** (FR-001-18) Given three consecutive changes that are still empty when each one's 10 s watch ends, then capture is suspended and `CAP-PRM-001` is raised; given three copies that each fill 1.5 s late, then capture keeps running and `CAP-PRM-001` is not raised.
- **AC-001-23** (FR-001-01) Given an empty change being watched, when a newer `changeCount` arrives, then the watch ends and the new change is stored exactly once.
- **AC-001-24** (FR-001-01) Given a change that is empty at first, then content landing 9.9 s after it first appeared is stored; content first read 10.0 s after is not stored and the change counts as empty (`CAP-VAL-001`).
- **AC-001-19** (FR-001-19) Given capture is Paused, then no pasteboard poll runs, the shared timer fires no more often than every 5 s while the tap watchdog and the folder re-resolve keep running within 5 s and 30 s of their previous run even when Pause and Resume alternate faster than those periods, and with neither registered no timer is scheduled; given a text copied while Paused, then after Resume it is never captured, and a text copied after Resume is; given Resume, then the 0.5 s tick is back and one check runs at once.

## 8. UI Inventory
Capture has no window of its own. Elements it contributes to, owned elsewhere:
| Element | Owner | Capture's role |
|---|---|---|
| Menu-bar icon states (active, paused, curated, warning dot) | FRD-008 | reflects capture mode and `CAP-*`/`STO-*` Notices |
| Notices entries | FRD-000 | raises CAP-PRM-001, CAP-LIM-001/003, CAP-IO-001 |
| "Pause Capture" and "Save Clipboard" menu items | FRD-008 / FRD-005 | invoke FR-001-19 |
| Privacy settings pane (ignored apps, Paste from Other Apps guidance) | FRD-008 | supplies the list consumed by FR-001-04 |
| Library row (kind icon, source icon) | FRD-003 | displays `ItemKind` and source from this FRD |

## 9. Assumptions to verify (architecture spikes)
1. macOS pasteboard privacy: the exact API for reading the access setting and the real enforcement on macOS 26 are unverified (only secondary reports found). FR-001-18(b) is a behavioural fallback that does not depend on the API; spike confirms.
2. Whether `org.nspasteboard.source` is supplied by enough apps to matter; the frontmost-app fallback is always available.
3. Phone detection is intentionally conservative; international formats beyond E.164-like strings may classify as `text`.

## 10. Out of Scope
Screenshot-file pickup (FRD-002). Image content analysis of any kind other than the on-device text recognition that feeds search (FRD-007 FR-007-23; A3 as amended 2026-11-19). Capturing file contents or file promises. Syncing or sharing clips (A1). Per-app capture rules beyond the ignored list. Capturing multiple pasteboard items as separate entries.
