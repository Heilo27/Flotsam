# FRD-008 — Onboarding, Permissions and Settings

**Status:** Draft · 2026-11-16 · Constitution: [TRUTHS.md](../TRUTHS.md) · PRD: [PRD.md](../PRD.md) (feature F8) · Errors: [FRD-000](FRD-000-ErrorSystem.md)
**Owns:** the settings registry (the single list of every setting key, type and default), settings persistence and validation, the Settings window and its panes, the permission model and its fallbacks, first-run onboarding, launch at login, the menu-bar item (icon states and menu), the ignored-apps list and its defaults, the screenshot-folder override picker, the About pane.
**Does not own:** the behaviour behind any setting (each registry row names its owner FR); hotkey recording and conflict rules ([FRD-005](FRD-005-ShortcutsTriggers.md)); retention, budget and capture-mode semantics ([FRD-007](FRD-007-RetentionStorage.md)); Shelf behaviour ([FRD-006](FRD-006-Shelf.md)); the error catalogue and Notices mechanism ([FRD-000](FRD-000-ErrorSystem.md)).

## Truth Test
- Serves: P1 — "anything you copied or screenshotted in the past 30 days is back": capture only works once the pasteboard-access setting and the screenshot folder are right, so first-run must get the user there in a few clicks, and the Library must keep working (copy-only) when Accessibility is refused.
- Supports: S4 — typed triggers and paste-back depend on Accessibility and Input Monitoring; this FRD is where those are requested, explained and recovered from. S3 — Shelf placement and enablement are set here.
- Violates: none. There is no account or sign-in (A1), no licence screen, update check, usage statistics or crash reporting (A4); v1.0 makes zero network calls, and Sparkle auto-update is DEFER (see `docs/CUT.md`).
- Verdict: KEEP. Settings are the cheapest place for scope to grow, so the registry in FR-008-01 is the gate: a key without an owner FR in another FRD, or without a row here, does not exist.

## 1. Purpose
Get a new user from "just installed" to "capturing and recoverable" without reading documentation, keep every preference in one typed registry so no two parts of the app disagree about a default, and degrade gracefully, never silently, when macOS withholds a permission.

## 2. User Stories
- As a new user, I am walked through the few permissions that matter, can skip any of them, and end up with a working Library either way.
- As a user who refused Accessibility, I can still search and copy my history, and the app tells me exactly what is reduced and how to fix it.
- As a user, I find every preference in one Settings window grouped as General, Library, Shortcuts, Triggers, Privacy, Storage.
- As a user, I tell Flotsam to ignore my password manager and any other app I name.
- As a user, I choose whether Flotsam starts at login, and if macOS blocks it I see why.
- As a user, I see at a glance from the menu-bar icon whether capture is on, paused or curated, and whether something needs attention.

- **FR-008-02** Persistence, validation, change delivery. Values live in the app's `UserDefaults` under the keys above. Every read goes through the typed registry accessor, never a raw string key. A boolean reads as `true`/`false`, and also as the spellings `UserDefaults` itself uses for a boolean (`1`/`0` and `YES`/`NO`, exactly: `defaults write -bool` and a `-key NO` launch argument produce them), so those are valid data and raise nothing; any other text for a boolean is a wrong type. A stored value that fails its validator (wrong type, unknown enum case, unresolvable bookmark, unusable chord: no ⌘ or ⌃, or a key code that is not a usable key per FR-005-02 b) is replaced by the default, the default is written back so `defaults read` shows it, and `SET-DAT-001` is raised once per launch per key (Notice, no HUD). A change is delivered to subscribers as an event with the key and new value and takes effect immediately, without restart; the settings control that made the change is the only writer, and a failed apply (for example `SET-OS-001`) reverts the stored value and the control.

**Settings window**
- **FR-008-03** Window. One Settings window, opened by ⌘, from the Library, and by "Settings…" in the menu-bar menu. A Notice or alert has no "Open Settings" action: a Notice is a message with a code and no fix-it path, and permission guidance points the user to macOS System Settings (the "Open System Settings" buttons, FR-008-06, FR-008-13), not to this window (TASK-530, 2026-11-19; a Notice that later needs a fix-it must add it here first and call the one open path). It is a single window (reopening focuses it) and every open brings it in front of the app the user was in and makes it the key window, so the next key typed goes to Settings, including when ⌘, is pressed in the Library over another app (the Library never activates Flotsam, and the system may refuse a plain activation request; the window then has the system activate Flotsam as a launch does, and Flotsam stays a menu-bar-only app with no Dock icon). The item shortcut editor and the setup guide come forward the same way, except that the setup guide Flotsam shows by itself at launch only asks for activation and never has the system force it, so a start at login does not take the keyboard from the app the user is in; a window closed before the system answers is not forced either. The same holds when the setup guide is already open: Flotsam's own launch-time show never forces it, and it never cancels a forced activation the user's own open is still waiting on (a user's explicit open outranks a passive show; a second user open replaces the first, so the system is asked once). A window the user had minimized to the Dock comes out of it and forward on every open, and counts as open while it does. The system is asked to activate Flotsam only when the app that was frontmost when the user opened the window is still frontmost after the grace (the request was refused); if the user has meanwhile switched to another app, Flotsam leaves that app in front. If no app was frontmost when the window was opened and none is after the grace, the activation is still forced; if one appeared in that time, it stays in front. It has a sidebar or toolbar of panes in this order: General, Library, Shortcuts, Types, Triggers, Privacy, Storage, Tips, About (the Types pane is FR-008-26, the Tips pane FR-008-27). It reopens on the last pane (`settings.lastPane`). Closing it with ⌘W or Escape discards nothing: every control applies at once; there is no Apply or Save button. All controls are reachable by keyboard, have VoiceOver labels from the catalogue, and the window follows the system appearance. Each pane's controls are exactly those listed in FR-008-04 to -09.
- **FR-008-04** General pane. One grouped form with a section header per group, in order: System, Screenshots, Shelf, Setup (the Library and Capture groups are the Library pane, FR-008-33). A control's explanatory note sits directly under that control's own label, inside the same row, so a note never drifts from the control it explains. Controls in order: System: Launch at Login (switch, FR-008-15); Screenshots: Pick up screenshots (switch, `screenshots.enabled`); Screenshot folder (shows the effective folder name; "Choose…" and "Use System Default", FR-008-10); "Import Recent Screenshots" (button, always enabled, runs FRD-002 FR-002-12 and shows the "Imported {n}" HUD with the real count, 0 included; onboarding step 5 runs the same action); Shelf: "Show shelf" (switch; switch labels are sentence case, FR-008-17 `shelf.enabled`, `ui.settings.shelf`; the label does not repeat the section header); placement popup `shelf.placement`; "Reveal on edge hover" switch `shelf.revealOnEdgeHover` (`ui.settings.revealAtEdge`, caption `ui.settings.revealAtEdgeHelp`: "The Shelf slides out when the pointer rests at the edge."), disabled when the Shelf is off or placement is Menu Bar; "Show edge bar" switch `shelf.edgeBar` (`ui.settings.edgeBar`, caption `ui.settings.edgeBarHelp`: "A thin bar marks the edge while the Shelf is hidden."), off by default and disabled under the same condition (the first is about the pointer opening the Shelf, the second about a visible marker; they are independent); Setup: "Show Setup Guide…" (reopens onboarding, FR-008-12). Rows use the native 13 pt row height. Every caption is one short line (a caption that needs more is cut down, not wrapped). Every pane is as tall as its content up to the height of the screen it opens on minus the window's own chrome, so the window is never taller than the screen. General holds about 630 pt of content so it shows whole on a laptop display with no scrolling; a pane that is still taller than its screen scrolls. A scrolling pane's viewport edge can fall mid-row, so no pane may be built taller than a laptop screen: when one grows past it, it is split by topic (as Library was split from General, TASK-529 round 3).
- **FR-008-05** Shortcuts pane. One row per registry shortcut (Open Library, Save Current Clipboard, New Clip…, Toggle Shelf, Paste Queue): the four that have a menu item are labelled by that menu entry's catalogue string (`ui.menu.*`), one command, one string, so the menu and this pane cannot disagree; Paste Queue has its own label. Each row has a label and the shortcut recorder field, the same control the item editor uses (FRD-005 FR-005-09): it shows the chord as keycaps, a click starts recording, and a clear control sits inside the field when the shortcut can be cleared (every row but Open Library). Recording, validation, conflict detection and the unbound state are FRD-005's (FR-005-01 to -04); this pane renders those rows from the FRD-005 registry and adds nothing. A footnote states that per-item shortcuts and triggers are set from the Library (⌘K).
- **FR-008-06** Triggers pane. Controls: "Expand typed triggers" switch (`triggers.enabled`); the permission status rows for Accessibility and Input Monitoring (FR-008-13) with "Open System Settings" buttons; the excluded-apps list (`triggers.excludedApps`) with add (application picker as in FR-008-11), remove, and "Reset to Defaults". While `triggers.enabled` is on but a permission is missing, the pane shows one line of inline text: while Accessibility is missing it is `ui.settings.triggersAccessibilityPaused` ("Accessibility is off, so typed triggers are paused. Turn it on in System Settings › Privacy & Security."); while Input Monitoring is missing it is the `SET-PRM-002` message. The error code stays `SET-PRM-001` for logging and the Notice; `SET-PRM-001`'s own text remains the copy-only HUD text (FR-008-14). The behaviour of triggers is FRD-005's.
- **FR-008-07** Privacy pane. Controls: the ignored-apps list (`privacy.ignoredApps`, FR-008-11); a read-only statement of what is never stored (transient and auto-generated pasteboard types) and what is stored encrypted (concealed copies, such as passwords from a password manager, which Library and Shelf show masked and which need the Mac's password or Touch ID to copy again; FRD-001 FR-001-04 and FR-001-25); the "Paste from Other Apps" status and guidance row (FR-008-13); a one-line statement that Flotsam makes no network connections. The pane has no control that sends anything anywhere.
- **FR-008-08** Storage pane. Layout only; every control, default and behaviour is FRD-007's (FR-007-08, -09, -11, -12 and §8 of that FRD): Keep history for; Image storage limit; Image quality; Capture mode; usage labels; Clear History…; Reveal Data Folder.
- **FR-008-09** About pane. App name, version and build, the licence line (MIT) with a "View Licence" button that opens the bundled licence text in a sheet, a "Copy Diagnostics" button (FRD-000 FR-000-14, HUD "Diagnostics copied"), and "Reveal Data Folder". There is no update check, no "Check for Updates" button and no link that Flotsam opens by itself; a "Project Page" link is allowed only as a user-clicked button that opens the default browser.
- **FR-008-10** Screenshot folder override. "Choose…" opens an `NSOpenPanel` limited to folders. The chosen folder is validated (exists, is a directory, readable and listable); failure → `SET-VAL-001` inline and the previous value stays. On success a security-scoped bookmark is stored in `screenshots.folderOverride` and the watcher restarts per FRD-002 FR-002-01. "Use System Default" clears the override. Reading a protected folder (Desktop, Documents, Downloads) may cause macOS to show its own folder-access prompt; the app triggers that prompt only when the user enables pickup, chooses a folder, or reaches the onboarding screenshots step, never at launch. If access is refused, pickup is paused and `SSP-IO-003` is shown by FRD-002; this pane shows the same message beside the folder name with a button to System Settings › Privacy & Security › Files and Folders.

**Privacy: ignored apps**
- **FR-008-11** Ignored apps (single definition of the list and its defaults). `privacy.ignoredApps` is a list of application bundle identifiers whose copies are never stored (FRD-001 FR-001-04 gate 4). The default is empty: password managers are not ignored, because their concealed copies are stored as encrypted secure items (FRD-001 FR-001-25); a user who wants a manager's copies dropped entirely adds it here. The list shows each app's icon and name when installed, otherwise the bundle identifier. "Add…" opens an `NSOpenPanel` limited to `.app` bundles (starting in /Applications) and reads the bundle identifier; a bundle without one, or a non-application → `SET-VAL-002`; duplicates are ignored silently. Remove deletes the row; "Add Password Managers" (`ui.settings.addPasswordManagers`, with the caption `ui.settings.addPasswordManagersHelp`) is a one-tap preset beside "Add…" that appends every identifier of the preset list that is not already present, keeps the user's own rows in their order, and needs no confirmation because each added row can be removed. The preset is fixed in the registry module, ships with the app and is never fetched or updated from anywhere; it holds the identifiers of Passwords, Keychain Access, 1Password 8, Bitwarden, KeePassXC, Proton Pass, NordPass and Keeper, each checked against the vendor's or Homebrew's published bundle identifier or the app's own Info.plist. An app absent from the preset is added by hand with "Add…". Choosing the preset is the user's explicit choice to have those apps' copies dropped entirely, including their concealed copies that would otherwise be stored encrypted (FRD-001 FR-001-25); "Reset to Defaults" empties the list after a confirmation (`settings.confirm.resetIgnored`, "Clear the ignored-apps list? Flotsam will store copies from every app, password managers included."). Changes take effect on the next pasteboard change. An item already in history is never deleted by adding its source app to the list (that is the user's explicit delete or Clear History, FRD-007); it is hidden from view while the app is on the list (FR-008-42).
- **FR-008-11a** Ignored-apps migration (once). Installs made before the default became empty may have the old six stored: `com.apple.keychainaccess`, `com.apple.Passwords`, `com.1password.1password`, `com.agilebits.onepassword7`, `com.bitwarden.desktop`, `org.keepassxc.keepassxc`. At the first launch of a version that carries this rule, before the list is read, a stored list that holds exactly those six (any order, no extras, no repeats) is replaced by the empty list. Any other stored list is the user's own and is kept unchanged, even one that contains some of the six. Nothing stored, or a value that does not read, is left to the normal default rules (FR-008-02). The migration runs once, recorded by a marker in the same store, so a user who later adds all six on purpose keeps them. It is migration bookkeeping, not a setting, and has no row in the registry.
- **FR-008-42** Ignored apps hide existing items (read-time, never destructive). While an application's bundle identifier is on `privacy.ignoredApps` (FR-008-11), every stored item whose source application is that identifier is hidden everywhere items are listed or counted: the Library list, grid and search results, the footer count and every sidebar count (FRD-003 FR-003-11, FR-003-12, including the Apps list), the Shelf (FRD-006) and any other reader of the library, whether pinned, noted or in a bundle. The hide is a listing rule only: a hotkey or trigger the user assigned to an item (FRD-004, FRD-005) keeps firing while the item is hidden, because an explicit assignment outranks the listing hide; the registry and the trigger snapshot read bindings by item, not through `Selection`, and a firing pastes the item's stored content as for a visible one. Nothing is deleted, rewritten or re-sourced: removing the application from the list shows its items again, with their tags, pins, notes and order intact; the change shows on the next read, with no restart. One query-layer rule owns this (`FlotsamStorage`, applied through `Selection`, so a new listing path cannot omit it): the match is exact on the stored source bundle identifier, as capture gate 4 matches it; an item with no source bundle identifier (a copy from another device, or an unknown source) is never hidden; identifiers are passed as bound arguments, never spliced into the query. Hiding does not change what the store holds: the Storage pane's usage, retention and Clear History (FRD-007) still act on every row, so a hidden item counts toward the size and ages out and clears like any other. A copy of the same content from another app dedupes onto the existing item and keeps its original source (FRD-001 FR-001-15), so such an item stays hidden while its original source is ignored. A Shelf drop from an ignored application is an explicit action (FRD-006 FR-006-13) and stays visible: at store time the drop's source bundle identifier is left empty when the source application is on the list (the source name is kept), so the rule above never matches it. That substitution is made in `FlotsamStorage` next to the hide rule (`IgnoredAppsGate`), the one home of what the ignored list means for stored items; it does not change for a later list edit. A drop that dedupes onto an existing item whose stored source is on the list wins over the hide: the same rule clears that item's source bundle identifier as the drop bumps it (name, tags, pins, notes and order untouched), so the item is listed and the Shelf can highlight and scroll to it; a drop onto an item whose source is not on the list leaves its source as it was. An item with no source bundle identifier is grouped in the Library sidebar's Apps list under "Unknown" ("Another device" for a remote copy), as every such item already is (FRD-003 FR-003-12, FRD-004 FR-004-10), and is filtered by that row; a drop from an ignored application is therefore counted and listed under Unknown, never dropped from the sidebar.

**Onboarding**
- **FR-008-12** First-run onboarding. Shown automatically in its own window on first launch (`onboarding.completed` false) and from General › "Show Setup Guide…". Every step is skippable, nothing is requested before its step, and each step states in one sentence what the permission is for and what stops working without it. The three permission steps (2 Clipboard access, 3 Paste for you, 4 Typed triggers) share one centred layout: a permission symbol (always in the accent colour), the title and purpose, then either what stops working and how to fix it, or, once the permission is granted, a status line with a green check in place of the warning. The status adds information instead of repeating the instruction (`ui.onboarding.clipboardGranted` "Access granted. Everything stays on this Mac."; `ui.onboarding.accessibilityGranted` "Access granted. Pasting now works in every app."; `ui.onboarding.inputMonitoringGranted` "Access granted. Keystrokes are never stored."); the green check appears for the granted status only. A row of progress dots (one per step, reached steps filled in the accent colour) replaces the "Step n of N" caption; VoiceOver still reads "Step n of N" (`ui.onboarding.stepOf`). The window has no zoom or minimise button. On every step Continue is the default button and the skip action ("Skip", or "Not Now" on steps 3 and 4) is a bordered secondary button on the leading side next to Back, apart from Continue, except step 4 while its permission is not granted, where "Not Now" is the default; once granted, Continue is the single prominent button and the way to grant ("Allow", "Open System Settings") is no longer offered. Steps in order: (1) Welcome: one sentence of what Flotsam does and the statement that it never sends anything off the Mac; (2) Clipboard access: shows the "Paste from Other Apps" instruction with a button to System Settings and a live status (every supported macOS gates pasteboard reads, FRD-001 FR-001-18, so the step is never skipped); (3) Paste for you (Accessibility, FR-008-13): "Allow" calls the system prompt for `AXIsProcessTrusted`; "Not Now" continues with the copy-only fallback of FR-008-14; (4) Typed triggers (Input Monitoring): offered, explained as optional, with "Not Now" as the visible default; (5) Screenshots: shows the effective folder read-only and a checked box "Import screenshots from the last 30 days" (FRD-002 FR-002-12), the first folder read happens here; it has no pickup switch and no folder button and writes no setting, because those controls belong to General alone (FR-008-17), and the sentence says where to change them; Continue imports only when pickup is on; (6) Hotkey: shows the Open Library chord with the shortcut recorder field (FRD-005) and its default; (7) Launch at login: switch, default on, applied by FR-008-15 only when the user continues; (8) Done: shows how to open the Library and where the menu-bar icon is, and offers to open it. "Back" and "Skip" are available on each step; closing the window at any point counts as finished and sets `onboarding.completed`, except that closing before step 8 leaves nothing half-applied (each step applies only what its own control set). The step the user is on is remembered as each step is left, so quitting midway (⌘Q closes no window) and relaunching resumes at that step instead of repeating finished ones; closing the window or "Show Setup Guide…" starts from step 1 again. Onboarding never blocks capture: capture is on from launch under default settings.

**Permissions**
- **FR-008-13 Permission model** (single definition). Flotsam asks for exactly these, in this order of importance:

  | Permission | Needed for | Detected by | Requested | If missing |
  |---|---|---|---|---|
  | Paste from Other Apps (gated pasteboard reads) | capture | FRD-001 FR-001-18 (`CAP-PRM-001`) | never programmatically; guidance only | capture suspended, warning dot, Notice |
  | Accessibility | paste-back, typed-trigger expansion | `AXIsProcessTrusted()` | onboarding step 3, first paste attempt, first trigger saved | copy-only fallback below |
  | Input Monitoring | typed-trigger detection | `CGPreflightListenEventAccess()` | when the first trigger is saved or `triggers.enabled` is turned on | triggers inert, `SET-PRM-002` |
  | Folder access (Desktop, Documents, Downloads, other) | screenshot pickup | listing the folder | FR-008-10 | pickup paused, `SSP-IO-003` |

  Rules: (a) no permission prompt appears at launch outside onboarding; (b) permission state is read fresh on every use and on app activation, never cached across launches; while the Settings window is visible it is re-read every 2 s so the status rows update after the user returns from System Settings or grants beside it (the re-read runs only while the pane showing the row is on screen in a visible window, never while Settings is closed, minimised, covered or on another pane, so it adds nothing to the idle wake-ups of truth S5; the onboarding window follows the same rule: its re-read stops while that window is closed, minimised or covered); (c) every permission row in Settings shows state (Granted, Not granted), what it enables, and a button that opens the matching System Settings pane; (d) a missing permission never disables unrelated features.
- **FR-008-14** Accessibility-denied fallback (copy-only mode). When Accessibility is not granted: the Library still opens, searches, previews and edits; choosing an item (Return, double-click) writes it to the system pasteboard with the app's own-write marker (FRD-001 FR-001-03), closes the Library, shows the HUD `SET-PRM-001` ("Accessibility is off, so Flotsam can't paste for you. The item is on your clipboard; press ⌘V."), and does not synthesise a keystroke; the Library footer shows the copy-only hint (`library.footer.copyOnly`, FRD-003) with an "Enable" button that opens the Accessibility pane of System Settings; typed triggers are inert (FRD-005 FR-005-10); global hotkeys that use the Carbon hotkey API keep working. Granting Accessibility takes effect without relaunch, detected by FR-008-13 rule (b). The HUD is shown at most once per paste attempt and repeated attempts keep copying.
- **FR-008-15** Launch at login. Implemented with `SMAppService.mainApp`. The switch state is read from `SMAppService.mainApp.status` every time the General pane appears, never from a stored copy; `.enabled` is on, `.requiresApproval` is shown as on with the caption "Waiting for approval in System Settings" and a button to Login Items, anything else is off. Toggling calls `register()` or `unregister()`; failure → `SET-OS-001` (HUD, toggle reverts). It is never registered silently: only the General switch or the onboarding switch (default on, applied when the user continues) can register it. macOS is not asked about the login item before the user reaches it: the status is read only while onboarding is on step 7 and while the General pane is open, never at launch or on other steps, because even reading `SMAppService.mainApp.status` makes macOS record the app in Background Task Management and show "Login Item Added". A Flotsam build that is not in /Applications may be refused by the system; that outcome is `SET-OS-001`.

**Menu bar**
- **FR-008-16** Menu-bar item. Flotsam is a menu-bar agent (no Dock icon, no main window). The status item shows a template icon in one of four states, each distinguishable without colour (distinct glyph shape plus the accessibility label): active; paused (capture mode `paused`); curated (capture mode `curated`); and a warning dot overlay while unacknowledged Warning or Error Notices exist (FRD-000 §9), combinable with any mode. The dot reflects problems that still exist: the owner of a long-lived condition (a missing permission, a tap that will not install, capture suspended) clears its Notice when the condition ends (FRD-000 FR-000-08), so a working app does not read "Needs attention". Clicking the icon opens its menu; dropping a payload on it follows FRD-006 FR-006-03. Menu contents in order: Open Library (shows the current chord); Save Current Clipboard (chord; the action is FRD-005 FR-005-06); New Clip… (chord, opens the Add Clip window, FRD-004 FR-004-19); Toggle Shelf (chord, hidden when `shelf.enabled` is off); separator; Pause Capture or Resume Capture (toggles `capture.mode` between `paused` and `active`; when the mode is `curated` the item reads "Resume Capture" and sets `active`); Pause For submenu (15 Minutes, 1 Hour, Until Tomorrow; shown only while the mode is `active`; pauses capture until that time, FRD-007 FR-007-12); Clear Recent submenu (Last 5 Minutes, Last Hour; each asks for confirmation before deleting, FRD-007 FR-007-11); Recent Notices submenu (FRD-000 §9; the last notices, newest first, with Dismiss All); separator; Settings… (⌘,); Show Setup Guide…; separator; Quit Flotsam (⌘Q). Chords are shown with modifiers in the system order ⌃⌥⇧⌘ (Toggle Shelf at ⌘ and ⇧ reads ⇧⌘9, here and in Settings). A menu item that has a chord shows the chord live, updating when it is changed in Settings. The menu is built from the registry and the capture mode at the time it opens, so it is never stale. Every title in the menu, its submenus and its choices is Title Case (hill-climb r2, TASK-529). The capture state is shown by the item itself: "Resume Capture" while Paused or Curated, "Pause Capture" while Active (no separate check mark), and by the icon. Toggle Shelf shows its chord whenever one is bound (it has none by default, FRD-005 FR-005-01). The key equivalents of Settings… and Quit Flotsam are the standard ones, drawn by the system menu with its own spacing.

**Quality**
- **FR-008-17** Accessibility and copy. Every control is operable by keyboard alone and labelled for VoiceOver; status is never conveyed by colour alone; text sizes follow the system; all strings are catalogue keys (FRD-000 FR-000-05). Descriptive text, control labels and messages use sentence case and plain words (for example "Pick up screenshots", not "Enable screenshot monitoring"). Following the macOS Human Interface Guidelines, buttons, menu items, popup values and window or section titles use Title Case (for example "Reveal Data Folder", "Right Edge", "Show Setup Guide…"). No setting appears twice in the UI except Capture mode (Storage pane and menu bar, both writing `capture.mode`) and Open Library's chord (Shortcuts pane and onboarding step 6, both writing `shortcuts.openLibrary`).
- **FR-008-18** Zero network. This FRD adds no network code of any kind. About, onboarding and Settings contain no remote content, no web view and no automatic link fetch; the only outbound action is a user click on a link that hands a URL to the default browser. A project check (grep for `URLSession`, `NWConnection`, `WKWebView`, Sparkle in the target) is part of the release checklist (A4).
- **FR-008-19** Text editing keys. Flotsam installs a main menu at launch (an app menu with Quit Flotsam, ⌘Q, and an Edit menu with Undo ⌘Z, Redo ⇧⌘Z, Cut ⌘X, Copy ⌘C, Paste ⌘V and Select All ⌘A, each sent to the focused control). The menu is never on screen, because Flotsam has no Dock icon; it exists so that those six keys work in every text field the app owns: the Library search field, the Organize overlays (tags, note, edit text, rename tag), the shortcut and trigger editor, and Settings. Without it, ⌘A in the edit card selects nothing and typing appends to the text. The menu adds no other key. It cannot collide with a Flotsam shortcut: FR-005-02 reserves ⌘Q, ⌘C, ⌘V, ⌘X, ⌘Z and ⌘A, only ⌘C is in the Library key map (FR-003-08), and there it yields to a selection in the search field, so the field's own copy is unchanged; and the Library, Shelf and recorder handle their own keys before the menu sees them.
- **FR-008-25** Restore Library Defaults. The Library pane's "Restore Library Defaults…" button opens a confirmation (title `ui.settings.resetLibraryTitle`, message `ui.settings.resetLibraryMessage`, buttons "Restore Defaults" and Cancel); Cancel changes nothing. Confirming writes the registry default back to exactly these keys and no others: `library.layout`, `library.viewMode`, `library.sort`, `library.panelSize`, `library.compactPanelSize`, `library.background`, `library.previewPreset`, `library.closeAfterPaste`, `library.resumeOnReopen`, `library.display`, `library.types`, `library.sidebarTypesCollapsed`. Every change is delivered like any other write (FR-008-02), so an open Library or Shelf follows at once and the pane's controls redraw. The reset never touches capture, screenshots, the Shelf's own settings, shortcuts, triggers, ignored apps, Storage (retention, image limit, quality, capture mode), or setup state, and never deletes an item: a reset can neither lose history, loosen a privacy rule nor unbind a hotkey. The set of reset keys is one list in the registry (`SettingKeys.resettable`); a new Library-appearance setting joins it by being added there.
- **FR-008-26** Types pane. One row per item type (the twelve of FRD-003 FR-003-12): a switch and move-up and move-down buttons (rows also drag to reorder). Listed (switched-on) types come first in their saved order; switched-off types follow in the default order. Switching a type on puts it at the end of the list; off removes it. The list is `library.types` and is what the Library's Types rows and the Shelf's type pills show and the order they show them in (FRD-003 FR-003-12, FRD-006 FR-006-22); a type that has no items is hidden there whatever the list says. A hidden type's items stay in All and in search and are not deleted. A stored list that names an unknown type or repeats one is invalid: it reads as the default and raises `SET-DAT-001` (FR-008-02). A type missing from a valid stored list is hidden. Caption: `ui.settings.typesHelp`.
- **FR-008-27** Tips pane. A static, read-only list of six short tips (title and one sentence each) from the catalogue (`ui.settings.tip*`): opening the Library without leaving the app, ⌘1 to ⌘9 and Return and ⇧Return, preview with Space or ⌘Y, sort and view and filter keys, per-item shortcuts and triggers with ⌘K, and dragging from the Shelf. It has no control, reads no setting and writes none. A tip names a key only if that key does that thing in the owning FRD.
- **FR-008-32** Capture cue setting. `capture.cue` (bool, default `true`, owner FRD-001 FR-001-30) is shown in the Library pane as a switch "Show a cue when something is captured" (`ui.settings.captureCue`) with the caption `ui.settings.captureCueHelp`: "A brief label that never takes focus or makes a sound." The value is read at each capture, so turning it off or on applies to the next capture with no relaunch.
- **FR-008-33** Library pane. One grouped form with a header per group, in order: Library, Capture. Controls in order: Library: Library layout (popup `library.layout`: Standard or Compact, with a caption from the catalogue, `ui.settings.libraryLayoutHelp`: "Compact is a small window; Space previews in the list's place."; the layout is read at each open, FRD-003 FR-003-06); Panel background (popup `library.background`, FRD-003 FR-003-21); Preview on open (popup `library.previewPreset`, FRD-003 FR-003-04, caption `ui.settings.previewPresetHelp`); Open on display (popup `library.display`, FRD-003 FR-003-03); Close after paste (switch `library.closeAfterPaste`, caption `ui.settings.closeAfterPasteHelp`); Resume where I left off (switch `library.resumeOnReopen`, caption `ui.settings.resumeOnReopenHelp`); "Restore Library Defaults…" (button, FR-008-25); Capture: Group copied files into a bundle (switch `capture.autoBundle`, with a caption from the catalogue, `ui.settings.autoBundleHelp`: "Off, each copied file is its own item."; read at each copy, FRD-001 FR-001-12); Show a cue when something is captured (switch `capture.cue`, with the caption `ui.settings.captureCueHelp`, FR-008-32). The Library rows' captions (`ui.settings.previewPresetHelp` "Standard layout only. Your saved size is kept.", `ui.settings.closeAfterPasteHelp` "Off keeps it open so you can paste several items.", `ui.settings.resumeOnReopenHelp` "Within 10 seconds, reopening keeps your search and selection.") state the rule without restating sizes. Why a separate pane (TASK-529 round 3, 2026-11-20): General held every one of these groups and was about 1170 pt tall, taller than a laptop display, so its last rows sat past the bottom edge of a scrolling window and the Library rows were cut mid-row in the capture; General and Library are now each about 630 pt or less, so each shows whole with no scrolling on a laptop display.

## 4. Data Requirements
- Persisted: the registry values above in `UserDefaults` (no database, no iCloud key-value store); onboarding completion; the last settings pane. A bookmark is persisted for the folder override only.
- Not persisted: permission states (read live), the Notices list (FRD-000 FR-000-13), launch-at-login (owned by macOS).
- Export, import or sync of settings: none.

## 5. Business Rules
- One key, one owner: the registry row names the FR that defines meaning and default; this FRD defines where and how it is shown. Changing a default means changing the registry row and the owner FR in the same commit.
- A permission can only be requested from a step or action that explains it first; the app never requests a permission to "see what happens".
- Settings never make a destructive change without a confirmation. The destructive controls (Clear History, shortening retention, reset ignored apps) live in FRD-007 and FR-008-11 and always confirm.
- Defaults are chosen so that the app is useful without opening Settings: capture on, 30 days, screenshots on, the capture cue on, Shelf on, Open Library on ⌃⌘V.

## 9. Assumptions and open items (flagged for Friday)
1. Flotsam is a menu-bar agent app with no Dock icon (`LSUIElement`); the PRD says "menu-bar icon" and never mentions a Dock presence. If a Dock icon is wanted, FR-008-16 changes.
2. The default ignored-apps list (FR-008-11) is empty since secure clips (FRD-001 FR-001-25); a password manager's concealed copy is stored encrypted rather than dropped. The six identifiers the old default held (1Password 7 and 8, Bitwarden, KeePassXC, Keychain Access, Passwords) were recalled from memory and are used only to recognise an untouched old list in the one-time migration (FR-008-11a). An identifier a user adds is theirs; a wrong one fails silently for that app. The "Add Password Managers" preset (FR-008-11) is not recalled from memory: its eight identifiers were each checked against published sources, and 1Password 7 (`com.agilebits.onepassword7`), Enpass (sources disagree between `in.sinew.Enpass-Desktop` and `in.sinew.Enpass-Desktop.App`), Dashlane, LastPass and Strongbox are left out until an identifier is confirmed.
3. Launch at login is on by default in onboarding step 7 (applied only on Continue). The PRD lists "launch at login" in first-run without a default; a clipboard history that is not running loses history, so the default favours P1. Ryan may prefer off.
4. Onboarding closing early counts as complete (no nagging). Re-offer exists via General › "Show Setup Guide…".
5. Settings live in `UserDefaults`, not the database, so a damaged database (`STO-DB-002`) never loses preferences.
6. Pane order and the "no Apply button" model follow macOS convention; no other app's Settings was consulted or copied.
7. The Carbon-based hotkey registration keeps working without Accessibility; this is the architect's reading of the platform and must be verified on macOS 26 before FR-008-14's "hotkeys keep working" line is relied on.
8. `TASTE.md` was not applied to visual choices; this FRD specifies behaviour and inventory, and visual design is Phase 6.
