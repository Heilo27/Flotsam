# FRD-003 — Library Panel

**Status:** Draft · 2026-11-16 · Constitution: [TRUTHS.md](../TRUTHS.md) · PRD: [PRD.md](../PRD.md) (feature F3) · Errors: [FRD-000](FRD-000-ErrorSystem.md)
**Owns:** the Library panel (window behaviour, layout, rows and grid, preview), search semantics, **the keyboard map (single source for every key the panel handles)**, paste-back, the Accessibility-denied fallback.
**Does not own:** the open-Library global hotkey binding ([FRD-005](FRD-005-ShortcutsTriggers.md)); the filter and sort model and organise actions ([FRD-004](FRD-004-Organize.md)); item data and schema ([FRD-007](FRD-007-RetentionStorage.md)).

## Truth Test
- Serves: P1 — this is the 3-second path: hotkey, type or arrow, Return, and the clip is pasted into the app you were using, with no mouse.
- Supports: S1 — sidebar filters and search by what a clip was (kind, tag, source app, note).
- Supports: S3 — a Library row can be dragged out to any app like a Shelf card (FR-003-45).
- Violates: none (no network use, including no link-metadata or favicon fetches).
- Verdict: KEEP

## 1. Purpose
A fast floating panel that appears over whatever you are doing, finds a clip, and pastes it back into the app you came from.

## 2. User Stories
- As a keyboard user, I press the hotkey, type two letters, press Return, and the text is pasted where my cursor was.
- As a user, I press ⌘3 to paste the third-most-recent clip without searching.
- As a user, I preview a clip (text, image, file) before pasting it.
- As a user without Accessibility permission, I still get the clip onto my clipboard and am told to press ⌘V.

## 3. Functional Requirements

**Panel behaviour**
- **FR-003-01** Window. The Library is an `NSPanel` with the non-activating style: it becomes key (receives typing) without making Flotsam the active app, so the previously active app stays frontmost. Floating level; collection behaviour allows all Spaces and full-screen auxiliary, so it appears over full-screen apps. One instance, created at launch and kept hidden (not rebuilt) between uses.
- **FR-003-02** Show and hide. The open-Library hotkey toggles. Before showing, the panel records the target app (frontmost application bundle id and process id), calls `captureNow` (FR-001-02), then shows. It hides on Esc (FR-003-08), the hotkey again, click outside, active-Space change, a different app becoming frontmost, or a Flotsam window opening, from the Library or from anywhere else (Settings with ⌘, or the menu-bar "Settings…" row, the setup guide from "Show Setup Guide…", the item shortcut-and-trigger editor with ⌘K or its context-menu row). The last hides the Library first, as its own step, whatever state the window was in (closed, open behind, or minimized in the Dock) and whatever opened it, so the window is never covered; it does not depend on the window taking key. A hide of any kind that arrives while the Library is still opening (after the hotkey, before the panel is on screen) is remembered: the open then finishes without showing the panel, so the Library never appears over the window that asked for it (TASK-531). The open-Library hotkey (and the menu item) pressed while the Library is still opening is such a hide: it cancels the open, and the Library does not appear (TASK-564, ruled by Friday 2026-11-19); the next press opens it again. The Shelf already behaves so by construction (FR-006-04): its reveal machine counts it visible from the moment it issues the show, so a hide in that interval cancels the load. The editor counts only when it opens (exactly one item selected, FR-005-09). Hiding without a paste restores nothing and writes nothing.
- **FR-003-03** Placement and size. Opens on the screen that contains the pointer, horizontally centred, its top edge one third of the way down the screen's visible frame. Default 760 x 480 pt, minimum 560 x 360, user-resizable; size is remembered (`library.panelSize`, FRD-008 registry). In the Compact layout (FR-003-06) the default is 520 x 520 pt (about square), the minimum 480 x 400, and its size is remembered separately (`library.compactPanelSize`), so switching layouts never overwrites the other layout's size. Placement is the same in both. The display is the one that contains the pointer unless `library.display` is Focus (FRD-008 registry): then it is the display that contains the centre of the focused window of the application the paste will target (the one frontmost when the Library was asked for), falling back to the pointer's display when that application has no on-screen window or the system gives no answer.
- **FR-003-04** Open state. Every open starts with: empty search, sidebar filter All, the newest item selected, list scrolled to top, preview closed, and the search field first responder. The previous filter and query are not restored, unless `library.resumeOnReopen` is on (default off) and the Library was hidden less than 10 seconds before: then the search, sidebar filter, selected item and preview state are kept as they were (compared against a timestamp taken when the panel hid; there is no timer, FRD-000 S5) and the list is refreshed, the selection staying on its item if it still exists. `library.previewPreset` (default Closed) changes only the preview and size part of a fresh open, and only in the Standard layout (the Compact layout has no preview column and ignores it): Open starts with the preview showing; Open with a larger panel also opens at least 960 x 600 pt (a larger remembered size is kept, the remembered size itself is never changed by the preset, and the screen's visible frame still caps it).
- **FR-003-05** Open performance. Hotkey press to panel visible with the search field focused: p95 ≤ 150 ms with 10,000 items (PRD). To meet it, the 50 newest rows are held in memory ready to render, further rows page in 50 at a time off the main thread, and nothing is rebuilt on open. Measured by the `library.open` signpost.

**Content and layout**
- **FR-003-06** Layout. Search field across the top; sidebar on the left (FR-003-12); results in the centre; optional preview pane on the right (FR-003-14); one-line footer hint bar along the bottom (FR-003-18). Two layouts, chosen in Settings, General (`library.layout`, FRD-008): Standard (default, as described) and Compact. Compact has no preview column: the panel is the sidebar and the results list, about square (FR-003-03). Space or ⌘Y (and the context menu's Preview, FR-003-22) still opens the preview, which then takes the results column's place with the sidebar staying, but only while a row is selected in a loaded list (FR-003-14); Esc, Space or ⌘Y closes it and the list returns (the Esc order is unchanged, FR-003-08); ↑ and ↓ still move the selection and the preview follows it. Selection, keyboard navigation, ⌘K, the context menu and every other key work the same in both layouts. The layout is read at each open, so a change in Settings applies to the next open (Settings opens in its own window and the Library hides first, FR-003-02). Open performance (FR-003-05) is unchanged: the layout adds one setting read at open and nothing is rebuilt. The tab order and the VoiceOver reading order are search, sidebar, results (or the preview when it has replaced the results) in both layouts.
- **FR-003-07** Views. List (default) and grid, toggled with ⌘G, remembered (`library.viewMode`). List row is 44 pt tall and contains, in order: kind icon or 32 pt thumbnail (images, screenshots, files, folders, bundles); primary line; secondary line; trailing badges. Primary line by kind: text and richText = first 2 lines, at most 140 characters; link = the URL; color = a swatch plus the colour string; phone and email = the value; image and screenshot = "Image" or "Screenshot" plus pixel size; file and folder = the name; bundle = "{n} items" plus its name when it has one (FRD-004 FR-004-42), otherwise the first two member names. Secondary line = source app name, relative time (relative date formatter; "Yesterday" or a date after 7 days), up to 3 tag chips plus "+n". Trailing badges: pin, trigger or shortcut present, ⌘1 to ⌘9 index for the first nine visible rows. Grid cell is 120 pt square: thumbnail or text card, with the same badges. Missing-file items show a "Missing" badge (`ui.library.missing`, "Missing"). An item is missing when it is a file, folder or bundle item and none of its members exist, using the same test as FR-003-15 step 1: each member is resolved by its bookmark, falling back to its stored path; a member that is a symbolic link whose target is gone counts as not existing, the same as paste. An empty bundle reads as Missing. The state is read from the disk each time a page of rows is read and is never stored, so a file restored or moved back clears it on the next read; it is not pushed live while a page stays on screen. Every consumer of rows (list, grid, Shelf) uses the same state.
- **FR-003-08** Keyboard map (the only definition). The search field is always first responder; any printable key types into it. Rows marked [FRD-004] or [FRD-005] execute actions defined there.

Keys are fixed in v1 (not user-remappable). A key not handled passes to the search field. ⌘A, ⌘V, ⌘X, ⌘Z and ⇧⌘Z are deliberately absent from the table: they are the standard text-editing keys, provided by the main menu (FRD-008 FR-008-19) and acting on the focused field, including the edit card's. ⌘C is in the table (it copies the selected row, the same as ⇧Return, through the same secure-item gate, FR-003-23) except while the search field has selected text, when it is the standard text copy; in the Organize overlays and the edit card, which own the keyboard, ⌘C is always the standard text copy.

**Search**
- **FR-003-09** Search semantics. The query is split on whitespace into tokens; an item matches when every token matches (AND). A token matches as a case-insensitive, diacritic-insensitive substring of any searchable field: plain text (first 10,000 characters), link URL, note, tag names, source app name, file and folder names of files and bundle members, a bundle's own name, kind label, the screenshot original file name, and the text recognised in an image or screenshot (FR-003-55). Results keep the active sort order (FRD-004); there is no relevance ranking. Searching runs within the active sidebar filter.
- **FR-003-10** Search performance. Typing a character to updated results: p95 ≤ 100 ms with 10,000 items (`library.search` signpost). Queries are cancelled and replaced as typing continues, so only the latest result renders.
- **FR-003-11** Result count and empty states. The footer shows "{n} items" for the current filter and query. No items at all shows the empty state (catalogue keys `ui.library.emptyTitle`, `ui.library.emptyBody`); no matches shows `ui.library.noResultsTitle`, `ui.library.noResultsBody`; a tag with no items and no search shows the empty-tag state (FR-003-50). None shows an error. Items whose source application is on the ignored-apps list are excluded from the list, this count, the sidebar counts and search, and are not deleted (FRD-008 FR-008-42).
- **FR-003-50** Loading, searching and empty-tag states (parity ticket TASK-546, 2026-11-19). (a) A load or search that is still running 150 ms after it started shows a small spinner with the caption `ui.library.loading` (or `ui.library.searching` while the search field has text): centred in the results area when no rows are on screen yet, else as a badge over the top of the rows, which stay. A load that finishes in under 150 ms shows no spinner at all, and while it runs with no rows the results area is blank, never the empty or no-matches text. The 150 ms is `BusyIndicator.delay`, the one constant the Shelf shares (FRD-006 FR-006-32). The delay is a single one-shot task, armed when a load starts and cancelled when it finishes, fails or the panel hides; a new keystroke during one load neither restarts it nor hides a spinner already showing. Nothing repeats and nothing runs while the panel is idle (truth S5, ADR-0004; FR-003-39). Paging a further 200 rows on scroll (FR-003-05) shows no spinner. (b) A tag chosen in the sidebar that has no items, with the search field empty, shows the empty-tag state (`ui.library.emptyTagTitle` with the tag's name, `ui.library.emptyTagBody`), not the no-matches text: nothing was searched for. A search that matches nothing inside a tag still shows no-matches (FR-003-11). Neither shows an error. A failed read still shows the inline error (FR-003-20), and cancels the spinner.
- **FR-003-55** Search finds text in images (parity ticket TASK-552, 2026-11-19; truth A3 as amended). The words that on-device text recognition finds in an image or screenshot (FRD-007 FR-007-23) are one more searchable field of that item, under exactly the FR-003-09 rules: the same search box, tokens, sidebar filter and sort, case- and diacritic-insensitive substring, AND over tokens, no relevance ranking. The Library and the Shelf (FR-006-22) share one query, so both match; there is no second search path. A matching image's row looks like any other result: no snippet, no highlight, no badge. An image that has not been read yet (just captured, or waiting in the backfill) does not match recognised text until it is; an image with no text, or one that could not be read, matches only on its other fields; a secure item is never read (FR-007-23). A3 limit: the recognised text is for search only. It is never shown in a row, the preview or anywhere else, never edited, exported, copied or pasted, and never put on a pasteboard or a drag; there is no control for it. Nothing in the panel makes a network request.

**Sidebar**
- **FR-003-12** Sidebar sections, top to bottom: All, Pinned, Notes, Shortcuts; Types (Text, Rich Text, Links, Colors, Phone Numbers, Emails, Images, Screenshots, Videos, Files, Folders, Bundles); Tags (colour dot and name, alphabetical); Apps (source apps with icons, ordered by item count, top 15). Each row shows an item count. Exactly one row is selected at a time; the selection is the single filter defined in FRD-004 FR-004-10. A row with count zero is shown dimmed except in Types, where empty types (Videos included) are hidden. The Types rows are the types listed in `library.types` (FRD-008 FR-008-26), in that order, each hidden while it has no items; a type switched off there has no row, and its items stay in All and in search. Videos is not an item type but a filter over files (FRD-004 FR-004-10), so `library.types` cannot list or switch it off: its row follows only the Videos count (shown at 1 or more, hidden at 0), never the Screenshots count. It sits right after Screenshots' place in the list; with Screenshots having no items it sits where Screenshots would be, and with Screenshots switched off it is the last Types row (TASK-561). Notes counts items that carry a note, Shortcuts counts items that carry a hotkey or a trigger, and Videos counts file and bundle items holding a video file (FRD-004 FR-004-10). The Bundles row is the "group" filter: a bundle is the one grouping kind (FRD-001 FR-001-12), so there is no second row for it.

**Preview**
- **FR-003-14** Preview pane (right side in the Standard layout, in place of the results in the Compact layout (FR-003-06), toggled by Space or ⌘Y, 280 pt wide in Standard, resizable with the panel). Content: text in full (up to 20,000 characters, then "Show more"); rich text rendered with its formatting (from its stored RTF; a rich text item with only HTML shows plain text, since importing HTML could fetch remote resources); link as the URL text only (no network fetch, no favicon, no metadata); colour as a large swatch with its hex and rgb values (for hex and `rgb()` notations; any other notation, and any malformed one (non-ASCII hex digits, an empty or non-numeric `rgb()` slot, a non-numeric alpha), shows its text and no swatch; out-of-range channels clamp to 0-255; colour notation, classification as a colour item as well as the swatch, takes ASCII digits only, so text with any other digits, such as Arabic-Indic or fullwidth, is plain text and not a colour; likewise a number too large to be a finite value, 309 or more digits, is plain text and not a colour), the hex and rgb values as the first rows of the metadata block after kind; image and screenshot scaled to fit; file, folder and bundle members as Quick Look previews with names (up to 20 members shown, then "and {n} more"). Below the content, a metadata block: kind, source app, copied date and time, first-copied date, copy count ("Times copied"), paste count, size on disk, pixel size for images, then one row per tag (colour dot and name) and its note, each only when it has any. Preview is read-only. Opening preview never changes the selection. In the Compact layout the preview replaces the results only when exactly one row is selected in a loaded list; when the history is empty, a search has no results (FR-003-11) or the load failed (FR-003-20), the message (with Retry for a failed load) owns the results column and the preview gives way to it, and it returns when a row is selected again. Esc still closes the preview first (FR-003-08), and typing in the search field with results leaves the preview open.
- **FR-003-13** Thumbnails. Rows and cells display thumbnails produced by the storage pipeline (FRD-007 FR-007-07). A row whose thumbnail is not yet ready shows the kind icon and swaps when ready; scrolling never blocks on thumbnail generation. The in-memory thumbnail cache is capped at 64 MB (least recently used) and is emptied when the last panel (Library or Shelf) closes, so an idle app holds none (S5; target state: `releaseMemory()` exists but is called from the panels by TASK-383, once they are built).

**Paste-back**
- **FR-003-15** Paste sequence. On Return, ⌥Return, ⇧Return or ⌘1 to ⌘9: (1) if the item references files, resolve bookmarks and drop members that no longer exist; none left → `LIB-DAT-001`, no paste, panel stays open; (2) write the item to the general pasteboard: every stored representation for text-bearing kinds (plain text only for ⌥Return); the stored image data for image and screenshot kinds (written through `NSImage` so the system supplies standard image types); every existing member as a file URL for file, folder and bundle kinds; (3) mark the write as Flotsam's own (FR-001-03); (4) increment the item's `pasteCount` and set `lastUsedAt` (FRD-007); (5) hide the panel, unless `library.closeAfterPaste` is off (default on), in which case the panel stays open and the next step does not wait for it to hide; (6) for paste actions only: wait until the panel is no longer visible plus a settle delay of 40 ms, confirm the frontmost application is still the recorded target, then post ⌘V (key code 9 with the Command flag, key down then key up) addressed to the recorded target's process (`CGEvent.postToPid`), not to the session event tap (FR-003-16). ⇧Return performs steps 1 to 5 only, and is logged as `paste.copy`, not `paste.back` (FRD-000 FR-000-11).
- **FR-003-16** Target app mismatch or post failure. If the frontmost application is not the recorded target after 250 ms, or the event cannot be posted, the item stays on the pasteboard, nothing is pasted, and `LIB-OS-001` shows a HUD. A pasted item is never re-written after the event is posted. The ⌘V is addressed to the target's process, and the poster re-reads the frontmost application and the target's running state immediately before posting; if the target is no longer frontmost or no longer running, nothing is posted and the same failure applies. The session event tap is not used for ⌘V, because it delivers to whichever application has focus when the window server routes the event, so a focus change after the check would paste the clip into a different app (security finding F4, TASK-345). *Trade-off:* a process-addressed event bypasses the window server's focus routing, so it reaches the target's own event queue; this was chosen over the session tap because a misdirected paste leaks the clip, while a target that ignores a process-addressed ⌘V only fails to paste (the item is on the pasteboard and the user can press ⌘V). `postToPid` reports no delivery failure, so such a target shows no `LIB-OS-001`. Whether any target class (sandboxed, Electron, Terminal) ignores a process-addressed ⌘V is not yet confirmed; the dogfood matrix (Assumption 2) must include it, and if one does, the fix is a per-bundle fallback decided then, not a silent return to the session tap.
- **FR-003-17** Accessibility denied. When `AXIsProcessTrusted()` is false, paste actions perform steps 1 to 5 of FR-003-15 only (same as ⇧Return) and show the HUD `SET-PRM-001`; the HUD throttle (FR-000-08) may suppress repeats, so the footer hint bar also shows, while permission is missing, the persistent text `ui.library.footerCopyOnly` ("Press ⌘V to paste"), and the panel closes after Return as usual. Everything else in the Library works without Accessibility.
- **FR-003-19** Latency. Return to ⌘V posted: p95 ≤ 150 ms (`paste.back` signpost, which a copy-only paste does not emit because it posts no ⌘V), excluding the target app's own handling. Task falsifier (TRUTHS P1): hotkey to pasted, for a clip from yesterday located by typing, has a median ≤ 3 s in the timed dogfood task.

**Hints, data errors, accessibility**
- **FR-003-18** Footer hint bar shows the three most relevant keys for the state (for example "Return Paste  ⌥Return Plain  Space Preview"), the active sort's name (FR-004-12) beside the item count, and the copy-only notice when applicable. With two or more rows selected the hints are "Return Start paste queue" and "Esc Clear selection"; while a paste queue waits (FR-003-25) the notice is its remaining count and that Esc cancels, in place of the copy-only notice (the Enable button stays). While Accessibility is denied (FR-003-17) the second hint is "⌘C Copy" (the copy-only key, FR-003-08) in place of "⌥Return Plain"; with Accessibility granted it stays "⌥Return Plain". All text comes from the catalogue.
- **FR-003-20** Data errors. An item whose stored data is missing at paste time is deleted and shown as `LIB-IO-001`. A failed database read shows `STO-DB-004` inline in the results area with a Retry button; the panel keeps working.
- **FR-003-21** Accessibility. Every control is reachable and operable by keyboard; rows expose VoiceOver labels in the form "{kind}, {primary text up to 100 characters}, from {app}, {relative time}, pinned" with row actions available via the VoiceOver actions menu; the panel respects Reduce Motion (no slide, fade only), Increase Contrast, and light and dark appearance, with the panel's background following the system unless `library.background` is Light or Dark, which fixes the panel's appearance (FRD-008 registry); hit targets are at least 44 pt tall; a visible focus ring marks the selection.
- **FR-003-22** Context menu (right-click, mouse path only). Entries in order: Paste, Paste as Plain Text, Copy, Preview, separator, Pin or Unpin, Tags..., Note..., Edit... (text only), Shortcut and Trigger... (exactly one non-secure item), Group into Bundle (two or more file, folder or bundle items), Rename... (exactly one bundle), Ungroup (bundle), separator, Reveal in Finder (where applicable), separator, Delete. Each performs the same action as its key in FR-003-08. Shortcut and Trigger... is shown only when the menu's target is exactly one item and that item is not secure; with several items selected it is absent, because ⌘K does nothing for them. A secure item's menu has neither Edit... nor Shortcut and Trigger... (FR-003-23, FR-005-09). The row and ⌘K follow one rule, so the row is offered exactly when ⌘K would open the editor. Note... and Edit... (exactly one item, Edit also a text kind that is not secure), Rename... and Ungroup (exactly one bundle) likewise each follow one rule, shared by the menu and the Library's organize actions, so a row is offered exactly when its key would act (`ItemActionRule`, TASK-558). The App's editor entry point applies the shortcut rule itself too: it opens the editor only for exactly one id that is not a secure item, and otherwise opens nothing and leaves the Library as it is.
- **FR-003-23** Secure items: authorise, then re-copy. A secure item (FRD-001 FR-001-25) is shown as the fixed mask, never its text, with a lock; when its Keychain key cannot be read on this Mac the row also shows an "Unavailable" badge (the same catalogue string in the Library and the Shelf). Every action that would put its text on the pasteboard (Return, ⌥Return, ⇧Return, double-click, ⌘C, Paste, Paste as Plain Text and Copy in the context menu, and the Shelf's FR-006-21) first checks that the key is readable (`LIB-DAT-002` if not, and no prompt is shown, since nothing could succeed) and then asks the device owner to authenticate (Touch ID, Apple Watch or the account password), every time and with no grace period. A cancelled or failed check is `LIB-OS-002` and nothing is written, recorded or pasted. On success the text is decrypted only then and written as plain text alone (the mode does not matter) with `org.nspasteboard.ConcealedType` plus the own-write markers (FRD-001 FR-001-03), so other apps and clipboard managers treat it as the password it is, Flotsam does not capture its own re-copy, and the clipboard-variable `{clipboard}` (FRD-005 FR-005-17) reads it as empty. Accepted trade-off: because the item is re-copied to the general pasteboard, a password manager's own auto-clear of the clipboard no longer limits how long the password is exposed there.
- **FR-003-24** Relative times stay current. While the panel is shown, every row's relative time (FR-003-07) and the age in its VoiceOver label (FR-003-21) advance without any other input: a row that read "2m ago" reads "3m ago" a minute later with the panel still open. Both strings are built from one reading of one clock per refresh, so they never disagree. A refresh is due when the soonest visible label would read differently, and every label is right within one step of a clock change: each second for a copy under a minute old ("5s ago"), then each minute and each hour, then each calendar day (counted on the calendar, so a day is 23 or 25 hours long across a daylight-saving change, but the refresh for the last day label is never later than the second the copy turns 7 days old, 604,800 s, so it becomes a date on time); a copy dated ahead of the clock (the clock was set back) reads "now" and is next refreshed a second after its date, not every second until then; a copy more than 7 days old reads as a date and never needs one. While the panel is hidden nothing is scheduled (idle wake-ups stay within FRD-001 FR-001-20, which counts only a hidden panel), and showing the panel reads the clock afresh.
- **FR-003-38** Hover row actions (mouse path only; every key and the context menu are unchanged). While the pointer is on a row (list) or cell (grid), a small strip appears on it with three buttons, in order: Copy, Pin or Unpin, Delete. Each is the context menu's entry of the same name (FR-003-22) and acts on the row exactly as that entry does: it acts on the pointer's row, or on the whole selection when that row is part of a multi-selection, selecting the row first when it is not selected. Pin or Unpin reads the same rule as the menu's entry. Delete takes the same path as Delete in the menu and ⌘⌫. The strip is drawn only for the hovered row, never changes the selection or the cursor by the pointer merely resting there, has a tooltip with each button's name, and is hidden from VoiceOver (the keys and the context menu are the accessible path, FR-003-21).
- **FR-003-39** Hover preview (mouse path only). When the pointer has rested on a row for 500 ms and the preview pane is closed (FR-003-14), the same preview content as the pane (FR-003-14) appears as a read-only card beside that row: below it, or above it when there is no room, never over the row or its strip. Moving to another row restarts the wait; leaving the row, any key or command, opening the preview pane (Space or ⌘Y), hiding the panel and opening it again all dismiss the card, and a row the pointer is still on does not bring it back until the pointer enters a row afresh. It does not change the selection or the cursor, takes no pointer input, loads nothing from the network (FR-003-14), and a secure item shows its mask only (FR-003-23). It adds no timer while the panel is idle: the wait exists only between the pointer entering a row and leaving it (S5). The Esc order (FR-003-08), the keys and the Space and ⌘Y preview are unchanged.
- **FR-003-25** Paste queue. Select two or more rows and press Return: the Library closes and those items, in list order, wait as a queue. Each press of the Paste Queue shortcut (`shortcuts.pasteQueue`, FR-005-01) pastes the next item into the frontmost app through the same sequence as a single paste (FR-003-15 to -17, including secure-item authentication, FR-003-23, and the pasteboard restore), so the queue is not a second paste path. The queue advances only after that item was pasted or, without Accessibility, copied (FR-003-17); an item whose paste fails with a transient error (for example the user switched apps, `LIB-OS-001`) stays at the head and the next press retries it, and an item that can no longer be read (`LIB-IO-001`, `LIB-DAT-001`, `LIB-DAT-002`) is reported and dropped. Without Accessibility each press copies the next item and shows `SET-PRM-001`; the user pastes with ⌘V. A short HUD reports the queue starting ("Paste queue ready: N items"), progress ("Pasted n of N"), finishing and cancelling. Esc in the Library cancels the queue (the last step of the Esc ladder, FR-003-08); starting another queue replaces it. A press with no queue shows "The paste queue is empty". With the Paste Queue shortcut unbound, Return with several rows selected shows "Set a Paste Queue shortcut in Settings first" and keeps the panel open. The queue is in memory only (gone at quit), adds no monitor or timer, and writes nothing to the library. All text comes from the catalogue.
- **FR-003-45** Drag out of rows. Dragging a row (list or grid) past the system drag threshold starts a standard drag session, the same one the Shelf uses (FRD-006 FR-006-10, FR-006-11: representations, `.copy` only, the drag pasteboard only, lazily provided, never captured as a clipboard change, the stacked drag image with a count badge, the outcome codes and their HUD rules). Which rows go: if the row is in the selection, the whole selection in on-screen order; if it is not, that row alone and the selection is unchanged. A plain click still selects and a double-click still pastes (FR-003-09, FR-003-15); a press that does not pass the threshold reads nothing. An accepted drop counts one paste per dragged row (FR-003-15 count rule, `pasteCount` and `lastUsedAt`) and hides the panel, as a paste does; a drag that is cancelled or dropped on nothing changes nothing and leaves the panel open. A secure row (FR-003-23, FR-006-21) asks the device owner to authenticate when the drag starts (past the threshold, never on a plain click or a selection change), every time with no grace period, and the key-readable check comes first (`LIB-DAT-002`, no prompt); the text is decrypted only after that and is offered as plain text with `org.nspasteboard.ConcealedType`. A cancelled or failed check (`LIB-OS-002`) skips that row like a row with nothing to drag; if no row remains, no drag starts and the error shows; releasing the mouse button while the prompt is up starts no drag. The prompt taking key from the panel is not a click outside, so the panel stays open for it. A Library drag dropped on the Shelf is an ordinary drop (FR-006-12, FR-006-13); the Shelf refuses only drags that began in the Shelf. When a drag begins, the hover strip and hover preview card (FR-003-38, FR-003-39) are dismissed; a press on a hover-strip button, or in the gaps of the strip, acts as that button or does nothing and never starts a drag. Drag-out has no keyboard equivalent: Paste and Copy are the keyboard paths. Reuses `ShelfDragOut`; no timer, no observer and no network use.

## 4. Data Requirements
- Reads items, tags, source apps and counts through the storage query layer (FRD-007); writes only `pasteCount` and `lastUsedAt`.
- Settings read (FRD-008 registry): `library.viewMode`, `library.panelSize`.
- In memory: target app (bundle id, pid), selected item ids, current query, cache of 50 newest rows, thumbnail LRU (64 MB); the row cache and the thumbnail LRU are released when the panel closes (S5; target state, wired by TASK-383).

## 5. Business Rules
- Paste-back never modifies stored items (no re-save of what was pasted).
- Paste count increments on every successful pasteboard placement from the Library, including ⇧Return and the Accessibility-denied fallback, and once per row for each accepted drag-out (FR-003-45).
- The panel never makes a network request.
- Search matches the text the system recognised in an image or screenshot (FR-003-55) and nothing else about its pixels. Recognised text is for search only (A3): it is never displayed, edited, exported, copied or put on any pasteboard or drag.
- Dragging out of a row never moves, renames or deletes an original file (the operation is copy), never writes the general pasteboard, and never puts a secure item's text on the drag pasteboard without the owner's authentication (FR-003-45).

## 6. Error States (codes in FRD-000 §7)
| Situation | Code | Behaviour |
|---|---|---|
| Target app changed or ⌘V could not be posted | LIB-OS-001 | item left on pasteboard; HUD |
| Stored data missing | LIB-IO-001 | item deleted; HUD |
| Referenced files all missing | LIB-DAT-001 | no paste; HUD; row marked Missing |
| Secure item copy not authorised | LIB-OS-002 | nothing written to the pasteboard; HUD (FRD-001 FR-001-25) |
| Secure item key missing or bytes unreadable | LIB-DAT-002 | no copy; HUD; row marked Unavailable |
| Accessibility not granted | SET-PRM-001 | copy-only; HUD and footer hint |
| Database read failed | STO-DB-004 | inline message with Retry |

## 7. Acceptance Criteria
- **AC-003-01** (FR-003-01,02) Given a text field in another app has focus, when the hotkey is pressed, then the panel appears over it, the other app stays active (its menu bar remains), typing goes to the search field, and pressing the hotkey again or Esc closes it with no change to the other app's text.
- **AC-003-01a** (FR-003-02) Given the Library is open, when ⌘, is pressed or "Settings…" is chosen from the menu-bar menu, then the Library hides and Settings is in front, whether Settings was closed, open behind another window, or minimized in the Dock; likewise "Show Setup Guide…" in the menu-bar menu and the setup guide; likewise ⌘K with exactly one item selected and the item editor. With no item or several selected, ⌘K opens nothing and the Library stays. Given the same request arrives in the instant after the hotkey, while the Library is still opening, then Settings (or the setup guide, or the editor) is in front and the Library never appears.
- **AC-003-60** (FR-003-02) Given the Library is closed and the open-Library hotkey is pressed, when the hotkey is pressed again in the instant before the panel is on screen, then the Library never appears; a third press, once nothing is opening, opens it. The same holds for the menu item.
- **AC-003-02** (FR-003-01) Given a full-screen app on a second display with the pointer there, then the panel opens on that display over the full-screen app.
- **AC-003-03** (FR-003-04) Given a previous session left a query, filter and preview open, then the next open shows empty search, filter All, newest item selected, preview closed.
- **AC-003-04** (FR-003-05) Given 10,000 items and a scripted hotkey press, then p95 time to visible and focused over 50 runs is ≤ 150 ms.
- **AC-003-05** (FR-003-07) Given a seeded library with one item of each kind, then each row's primary line follows FR-003-07 and the first nine rows show ⌘1 to ⌘9 badges.
- **AC-003-05a** (FR-003-07) Given a file item, a folder item and a bundle item, when their files are deleted (for the bundle, all of its members), then the next read of rows marks each one Missing and the row shows the "Missing" badge; items whose files exist, a bundle with one member left, and every non-file kind are not marked; an empty bundle reads as Missing; restoring the file clears the mark on the next read.
- **AC-003-06** (FR-003-08) Given the panel is open, then each key in the table performs its action; with a non-empty query, Space types a space and does not toggle preview; ⌘Y toggles preview regardless.
- **AC-003-07** (FR-003-08) Given the query is "x" and Esc is pressed three times with preview open, then the first clears the query, the second closes preview, the third closes the panel. With three rows selected and an empty query and no preview, the first Esc leaves only the cursor row selected and the second closes the panel.
- **AC-003-08** (FR-003-09) Given items "Résumé draft", note "for Anna", tagged "work", from Safari, then queries `resume`, `anna`, `work`, `safari draft` each match it, and `resume zzz` does not.
- **AC-003-09** (FR-003-10) Given 10,000 items, then p95 latency from keystroke to results is ≤ 100 ms over 100 queries.
- **AC-003-10** (FR-003-15) Given Accessibility is granted and a text field is focused in Notes, Terminal, Safari, Xcode and VS Code, when Return is pressed on a text item, then the text is pasted in each; ⌥Return on a rich item pastes plain text in Notes.
- **AC-003-11** (FR-003-15) Given an image item and a bundle of 3 files, then Return pastes the image into Preview/Notes and the 3 files into a Finder window; if one bundle member was deleted, 2 are pasted; if all were deleted, nothing is pasted and `LIB-DAT-001` is shown.
- **AC-003-12** (FR-003-15,19) Given a paste, then `pasteCount` is incremented once, no new history item appears (own-write skipped), and p95 Return to ⌘V post is ≤ 150 ms.
- **AC-003-13** (FR-003-16) Given the user switches apps during the 250 ms window, then nothing is pasted, the item is on the pasteboard and `LIB-OS-001` shows.
- **AC-003-14** (FR-003-17) Given Accessibility is revoked, when Return is pressed, then the item is on the pasteboard, the HUD `SET-PRM-001` shows, the footer shows the copy-only notice on the next open, and the panel closes.
- **AC-003-15** (FR-003-14) Given a link item, then preview shows only the URL and no network request is made during the session (verified by a network monitor).
- **AC-003-16** (FR-003-12) Given tags "work" (3 items) and "home" (0 items) and no Emails in the library, then Tags shows both with counts, "home" dimmed, and Types has no Emails row.
- **AC-003-16b** (FR-003-12) Given 2 items with a note, 1 with a hotkey and 1 with a trigger, and 3 `.mov` files, then Notes shows 2, Shortcuts shows 2 and Videos shows 3 (right after Screenshots); selecting a row lists exactly that many items; with no video file stored, Types has no Videos row; with 3 video files and no screenshot, Videos still shows 3 (and likewise with Screenshots switched off in `library.types`); and each count updates within 200 ms of the change (FR-004-13).
- **AC-003-17** (FR-003-21) Given VoiceOver on, then a row reads as specified, all actions are reachable by keyboard only, and Reduce Motion removes slide animation.
- **AC-003-18** (FR-003-08) Given two items selected with ⇧↓, then ⌥Return, ⇧Return and ⌘C are disabled, Return starts a paste queue (AC-003-30), and ⌘P pins both.
- **AC-003-19** (FR-003-23) Given a secure item and a cancelled Touch ID prompt, when Return, ⇧Return or ⌘C is used, then `LIB-OS-002` shows, nothing is written to the pasteboard and nothing is pasted; given the key is gone, then `LIB-DAT-002` shows with no prompt; given the prompt succeeds, then the pasteboard holds the plain text with `ConcealedType` and the own-write markers, Flotsam does not capture it again, and a following expansion's `{clipboard}` is empty; given a second paste, then the prompt appears again; the row and its Shelf card show only the mask, with an "Unavailable" badge when the key is gone.

- **AC-003-38** (FR-003-38) Given the pointer on a row, then Copy, Pin or Unpin and Delete show on it, in that order; clicking Pin pins the row (the button reads Unpin once it is pinned), Copy copies it without pasting, Delete deletes it through the context menu's path; with the pointer away or on another row the strip is not drawn on this row, the selection and cursor do not change by hovering, and VoiceOver reads the row as in FR-003-21 with no strip.

- **AC-003-30** (FR-003-25,08,18) Given three items selected and the Paste Queue shortcut set, when Return is pressed, then the panel closes and the HUD reads "Paste queue ready: 3 items"; each press of the shortcut pastes the next item into the focused app in list order and the third press shows the finished HUD; a press after that shows the empty HUD. - **AC-003-45** (FR-003-45) Given a text row, an image row and a bundle of 3 files, when each is dragged from the Library into a text field, Preview and a Finder window, then the text is inserted, the image arrives and 3 file copies are created with the originals untouched, and the general pasteboard's `changeCount` does not change; given rows A and B selected, when C (outside the selection) is dragged, then only C goes and the selection is unchanged, and when A is dragged then A and B go in on-screen order; given an accepted drop, then each dragged row's `pasteCount` rises by 1 (a bundle by 1) and the panel hides, and given Esc or a drop on nothing, nothing changes and the panel stays; given a click, a ⌘-click, a ⇧-click and a double-click on rows, they select, toggle, extend and paste as before and no drag starts; given a secure row, a click or arrow-key selection shows no prompt, a drag asks the owner to authenticate once, a cancelled prompt starts no drag and shows `LIB-OS-002`, a missing key shows `LIB-DAT-002` with no prompt, a successful check drops text equal to the secret carrying `ConcealedType`, the panel stays open while the prompt is up, and a drag of plain row A with secure row B whose prompt is cancelled still drags A; given the pointer on a row so its strip and preview card show, when the row is dragged, then both are gone, and pressing Pin on the strip pins the row and starts no drag.

- **AC-003-55** (FR-003-55) Given an image whose pixels show "Invoice 4471" and that has no note, tag or text, when its recognition has finished and the user types `invoice`, `4471 INVOICE` or `inv`, then it is listed in the Library and in the Shelf, and `invoicex` does not list it; given a screenshot showing "Résumé", then `resume` lists it; given the same image before recognition has run, then none of those queries lists it; given a search that matches only recognised text, then the row looks the same as any other result and no control, menu item, preview or drag anywhere shows, copies or exports the recognised text; given a sidebar filter on another type, then the image is not listed (FR-003-09).

## 9. Assumptions to verify (architecture spikes)
1. A non-activating `NSPanel` that is key accepts text input while leaving the previous app frontmost, on macOS 26, including over full-screen apps.
2. The 40 ms settle delay and 250 ms window are sufficient across Terminal, Electron and browser targets; tune from the dogfood matrix.
3. Search at 10,000 items meets 100 ms with SQLite full-text indexing; the index design is FRD-007's (spike confirms trigram or scan strategy).
4. The default open-Library hotkey (FRD-005) does not collide with common system or app shortcuts.

## 10. Out of Scope
Remappable in-panel keys. Relevance ranking, search operators and saved searches. Pasting several selected items at once. Link metadata, favicons or any network preview. Showing, editing, exporting or copying out the text recognised in images (A3: that text is for search only, FR-003-55). Sharing or AirDrop (NOT DOING).
