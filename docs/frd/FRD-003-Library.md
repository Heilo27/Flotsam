# FRD-003 — Library Panel

**Status:** Draft · 2026-11-16 · Constitution: [TRUTHS.md](../TRUTHS.md) · PRD: [PRD.md](../PRD.md) (feature F3) · Errors: [FRD-000](FRD-000-ErrorSystem.md)
**Owns:** the Library panel (window behaviour, layout, rows and grid, preview), search semantics, **the keyboard map (single source for every key the panel handles)**, paste-back, the Accessibility-denied fallback.
**Does not own:** the open-Library global hotkey binding ([FRD-005](FRD-005-ShortcutsTriggers.md)); the filter and sort model and organise actions ([FRD-004](FRD-004-Organize.md)); item data and schema ([FRD-007](FRD-007-RetentionStorage.md)).

## Truth Test
- Serves: P1 — this is the 3-second path: hotkey, type or arrow, Return, and the clip is pasted into the app you were using, with no mouse.
- Supports: S1 — sidebar filters and search by what a clip was (kind, tag, source app, note).
- Supports: S3 — a Library row can be dragged out to any app like a Shelf card (FR-003-45).
- Violates: none (no network use, including no link-metadata or favicon fetches).
- Verdict: KEEP

## 1. Purpose
A fast floating panel that appears over whatever you are doing, finds a clip, and pastes it back into the app you came from.

## 2. User Stories
- As a keyboard user, I press the hotkey, type two letters, press Return, and the text is pasted where my cursor was.
- As a user, I press ⌘3 to paste the third-most-recent clip without searching.
- As a user, I preview a clip (text, image, file) before pasting it.
- As a user without Accessibility permission, I still get the clip onto my clipboard and am told to press ⌘V.

## 3. Functional Requirements

**Panel behaviour**
- **FR-003-01** Window. The Library is an `NSPanel` with the non-activating style: it becomes key (receives typing) without making Flotsam the active app, so the previously active app stays frontmost. Floating level; collection behaviour allows all Spaces and full-screen auxiliary, so it appears over full-screen apps. One instance, created at launch and kept hidden (not rebuilt) between uses.
- **FR-003-02** Show and hide. The open-Library hotkey toggles. Before showing, the panel records the target app (frontmost application bundle id and process id), calls `captureNow` (FR-001-02), then shows. It hides on Esc (FR-003-08), the hotkey again, click outside, active-Space change, a different app becoming frontmost, or a Flotsam window opening, from the Library or from anywhere else (Settings with ⌘, or the menu-bar "Settings…" row, the setup guide from "Show Setup Guide…", the item shortcut-and-trigger editor with ⌘K or its context-menu row). The last hides the Library first, as its own step, whatever state the window was in (closed, open behind, or minimized in the Dock) and whatever opened it, so the window is never covered; it does not depend on the window taking key. A hide of any kind that arrives while the Library is still opening (after the hotkey, before the panel is on screen) is remembered: the open then finishes without showing the panel, so the Library never appears over the window that asked for it (TASK-531). The open-Library hotkey (and the menu item) pressed while the Library is still opening is such a hide: it cancels the open, and the Library does not appear (TASK-564, ruled by Friday 2026-11-19); the next press opens it again. The Shelf already behaves so by construction (FR-006-04): its reveal machine counts it visible from the moment it issues the show, so a hide in that interval cancels the load. The editor counts only when it opens (exactly one item selected, FR-005-09). Hiding without a paste restores nothing and writes nothing.
- **FR-003-03** Placement and size. Opens on the screen that contains the pointer, horizontally centred, its top edge one third of the way down the screen's visible frame. Default 760 x 480 pt, minimum 560 x 360, user-resizable; size is remembered (`library.panelSize`, FRD-008 registry). In the Compact layout (FR-003-06) the default is 520 x 520 pt (about square), the minimum 480 x 400, and its size is remembered separately (`library.compactPanelSize`), so switching layouts never overwrites the other layout's size. Placement is the same in both. No column collapses as the panel narrows: the minimum size is what keeps the sidebar and the results list usable, so the sidebar, results and (Standard, when open) preview stay visible down to it, and the tab order and VoiceOver order (FR-003-06) never change with the width (TASK-560, 2026-11-19). The display is the one that contains the pointer unless `library.display` is Focus (FRD-008 registry): then it is the display that contains the centre of the focused window of the application the paste will target (the one frontmost when the Library was asked for), falling back to the pointer's display when that application has no on-screen window or the system gives no answer.
- **FR-003-04** Open state. Every open starts with: empty search, sidebar filter All, the newest item selected, list scrolled to top, preview closed, and the search field first responder. The search field is the strongest control in the header: the text-field surface with a 1 pt control-edge border in both appearances and a 2 pt accent ring while it has focus (hill-climb r2, TASK-529). The previous filter and query are not restored, unless `library.resumeOnReopen` is on (default off) and the Library was hidden less than 10 seconds before: then the search, sidebar filter, selected item and preview state are kept as they were (compared against a timestamp taken when the panel hid; there is no timer, FRD-000 S5) and the list is refreshed, the selection staying on its item if it still exists. `library.previewPreset` (default Closed) changes only the preview and size part of a fresh open, and only in the Standard layout (the Compact layout has no preview column and ignores it): Open starts with the preview showing; Open with a larger panel also opens at least 960 x 600 pt (a larger remembered size is kept, the remembered size itself is never changed by the preset, and the screen's visible frame still caps it).
- **FR-003-05** Open performance. Hotkey press to panel visible with the search field focused: p95 ≤ 150 ms with 10,000 items (PRD). To meet it, the 50 newest rows are held in memory ready to render, further rows page in 50 at a time off the main thread, and nothing is rebuilt on open. The held rows are released when the panel hides and reloaded on the next open (FR-003-13). Measured by the `library.open` signpost.

**Content and layout**
- **FR-003-06** Layout. Search field across the top; sidebar on the left (FR-003-12); results in the centre; optional preview pane on the right (FR-003-14); one-line footer hint bar along the bottom (FR-003-18). Two layouts, chosen in Settings, Library (`library.layout`, FRD-008): Standard (default, as described) and Compact. Compact has no preview column: the panel is the sidebar and the results list, about square (FR-003-03). Space or ⌘Y (and the context menu's Preview, FR-003-22) still opens the preview, which then takes the results column's place with the sidebar staying, but only while a row is selected in a loaded list (FR-003-14); Esc, Space or ⌘Y closes it and the list returns (the Esc order is unchanged, FR-003-08); ↑ and ↓ still move the selection and the preview follows it. Selection, keyboard navigation, ⌘K, the context menu and every other key work the same in both layouts. The layout is read at each open, so a change in Settings applies to the next open (Settings opens in its own window and the Library hides first, FR-003-02). Open performance (FR-003-05) is unchanged: the layout adds one setting read at open and nothing is rebuilt. The tab order and the VoiceOver reading order are search, sidebar, results (or the preview when it has replaced the results) in both layouts.
- **FR-003-07** Views. List (default) and grid, toggled with ⌘G, remembered (`library.viewMode`). List row is 44 pt tall and contains, in order: a 32 pt lead (hill-climb r4, TASK-529: a row must be recognisable at a glance): the thumbnail for images, screenshots, files, folders and bundles; a colour swatch for colour items; for every other kind the source application's own icon (20 pt, read from the item's stored source bundle ID through `NSWorkspace`, cached for the session, never fetched from the network), and the kind's glyph when the item has no source application or that application is no longer installed; primary line; secondary line; trailing badges. Primary line by kind: text and richText = first 2 lines, at most 140 characters; link = the URL; color = a swatch plus the colour string; phone and email = the value; image and screenshot = "Image" or "Screenshot" plus pixel size; file and folder = the name; bundle = "{n} items" plus its name when it has one (FRD-004 FR-004-42), otherwise the first two member names. Secondary line = source app name, relative time (relative date formatter; "Yesterday" or a date after 7 days), up to 3 tag chips plus "+n". Trailing badges: pin, trigger or shortcut present, ⌘1 to ⌘9 index for the first nine visible rows. Grid cell is 120 pt square: thumbnail or text card, with the same badges. Missing-file items show a "Missing" badge (`ui.library.missing`, "Missing"). An item is missing when it is a file, folder or bundle item and none of its members exist, using the same test as FR-003-15 step 1: each member is resolved by its bookmark, falling back to its stored path; a member that is a symbolic link whose target is gone counts as not existing, the same as paste. An empty bundle reads as Missing. The state is read from the disk each time a page of rows is read and is never stored, so a file restored or moved back clears it on the next read; it is not pushed live while a page stays on screen. Every consumer of rows (list, grid, Shelf) uses the same state. Scrolling never clips content (hill-climb r2 and r3, TASK-529). The list's viewport is a whole number of rows (`LibraryLayout.listFit`): rows are 44 pt tall with a gap of at least 2 pt (the height left over is shared out as extra gap, so the viewport is exactly a whole number of rows plus the top margin), the first row sits 4 pt below the top, the scroll content ends one gap below the last row, and scrolling snaps to a row. The edge above the footer therefore falls between two rows at rest and at every stop, so no row is ever cut and the list needs no fade. The grid has no whole-row viewport: it keeps 10 pt content margins and a 16 pt fade at its bottom edge, so no cell touches the panel's edge and a cut cell dissolves instead of ending mid-glyph. The sidebar follows the same rule by lines (FR-003-12). A row's title truncates by the width actually left, not by a character count: nothing in the row reserves room for a badge or index that is not there. While the row is hovered, the room for the hover strip (86 pt) is reserved and the row's own badges and index give way to it (FR-003-38). The selected row uses the one opaque selection fill (DESIGN section 2.2), the only accent-filled surface in the Library (the sidebar's selected row is a neutral wash, FR-003-12) with its row corner radius (`DesignToken.Radius.row`, 8 pt); on it the secondary line and the index badge are the primary text colour at 82% (never the faded `.secondary`), and the tag chips are drawn in the primary colour over a stronger wash so they stay legible. The shortcut-or-trigger badge is the keyboard glyph (not the command glyph, so it is never read as part of a ⌘1 to ⌘9 index); off the selection the index badge is drawn at 75% of the primary text colour.
- **FR-003-08** Keyboard map (the only definition). The search field is always first responder; any printable key types into it. Rows marked [FRD-004] or [FRD-005] execute actions defined there.

A key not handled passes to the search field. ⌘A, ⌘V, ⌘X, ⌘Z and ⇧⌘Z are deliberately absent from the table: they are the standard text-editing keys, provided by the main menu (FRD-008 FR-008-19) and acting on the focused field, including the edit card's. ⌘C is in the table (it copies the selected row, the same as ⇧Return, through the same secure-item gate, FR-003-23) except while the search field has selected text, when it is the standard text copy; in the Organize overlays and the edit card, which own the keyboard, ⌘C is always the standard text copy.

**Search**
- **FR-003-09** Search semantics. The query is split on whitespace into tokens; an item matches when every token matches (AND). A token matches as a case-insensitive, diacritic-insensitive substring of any searchable field: plain text (first 10,000 characters), link URL, note, tag names, source app name, file and folder names of files and bundle members, a bundle's own name, kind label, the screenshot original file name, and the text recognised in an image or screenshot (FR-003-55). Results keep the active sort order (FRD-004); there is no relevance ranking. Searching runs within the active sidebar filter.
- **FR-003-10** Search performance. Typing a character to updated results: p95 ≤ 100 ms with 10,000 items (`library.search` signpost). Queries are cancelled and replaced as typing continues, so only the latest result renders.
- **FR-003-11** Result count and empty states. The footer shows "{n} items" for the current filter and query. No items at all shows the empty state (catalogue keys `ui.library.emptyTitle`, `ui.library.emptyBody`); no matches shows `ui.library.noResultsTitle`, `ui.library.noResultsBody`; a tag with no items and no search shows the empty-tag state (FR-003-50). Each empty state is a symbol above its title and body (an empty history `doc.on.clipboard`, a tag with no items `tag`, no matches `magnifyingglass`, an error `exclamationmark.triangle`), and a state with an action offers it as a bordered button (no matches: "Clear Search", `ui.btn.clearSearch`). None shows an error. Items whose source application is on the ignored-apps list are excluded from the list, this count, the sidebar counts and search, and are not deleted (FRD-008 FR-008-42).
- **FR-003-50** Loading, searching and empty-tag states (parity ticket TASK-546, 2026-11-19). (a) A load or search that is still running 150 ms after it started shows a small spinner with the caption `ui.library.loading` (or `ui.library.searching` while the search field has text): centred in the results area when no rows are on screen yet, else as a badge over the top of the rows, which stay. A load that finishes in under 150 ms shows no spinner at all, and while it runs with no rows the results area is blank, never the empty or no-matches text. The 150 ms is `BusyIndicator.delay`, the one constant the Shelf shares (FRD-006 FR-006-32). The delay is a single one-shot task, armed when a load starts and cancelled when it finishes, fails or the panel hides; a new keystroke during one load neither restarts it nor hides a spinner already showing. Nothing repeats and nothing runs while the panel is idle (truth S5, ADR-0004; FR-003-39). Paging a further 200 rows on scroll (FR-003-05) shows no spinner. (b) A tag chosen in the sidebar that has no items, with the search field empty, shows the empty-tag state (`ui.library.emptyTagTitle` with the tag's name, `ui.library.emptyTagBody`), not the no-matches text: nothing was searched for. A search that matches nothing inside a tag still shows no-matches (FR-003-11). Neither shows an error. A failed read still shows the inline error (FR-003-20), and cancels the spinner.
- **FR-003-55** Search finds text in images (parity ticket TASK-552, 2026-11-19; truth A3 as amended). The words that on-device text recognition finds in an image or screenshot (FRD-007 FR-007-23) are one more searchable field of that item, under exactly the FR-003-09 rules: the same search box, tokens, sidebar filter and sort, case- and diacritic-insensitive substring, AND over tokens, no relevance ranking. The Library and the Shelf (FR-006-22) share one query, so both match; there is no second search path. A matching image's row looks like any other result: no snippet, no highlight, no badge. An image that has not been read yet (just captured, or waiting in the backfill) does not match recognised text until it is; an image with no text, or one that could not be read, matches only on its other fields; a secure item is never read (FR-007-23). A3 limit: the recognised text is for search only. It is never shown in a row, the preview or anywhere else, never edited, exported, copied or pasted, and never put on a pasteboard or a drag; there is no control for it. Nothing in the panel makes a network request.

**Sidebar**
- **FR-003-12** Sidebar sections, top to bottom: All, Pinned, Notes, Shortcuts; Types (Text, Rich Text, Links, Colors, Phone Numbers, Emails, Images, Screenshots, Videos, Files, Folders, Bundles); Tags (colour dot and name, alphabetical); Apps (source apps with icons, ordered by item count, top 15). Each row shows an item count, except while a search is active, when the counts are hidden because they describe the whole history, not the results (the footer carries the result count, FR-003-11). The Types section is a collapsible disclosure: its header is a button with a chevron (tooltip and VoiceOver hint "Hide Types" or "Show Types", `ui.library.typesHide`, `ui.library.typesShow`), expanded by default, and the choice is remembered in `library.sidebarTypesCollapsed` (FRD-008 FR-008-01, a look-only setting that Restore Library Defaults resets, FR-008-25). While Types is collapsed its rows are hidden except the one that is the active filter, so the selection is never invisible, and the up and down filter keys skip the hidden rows. Hierarchy (hill-climb r3): every row leads with a 12 pt SF Symbol (the kind's own symbol for a type, so the sidebar and the list agree; tray for All, pin, tag, app, note, keyboard and film for the others), the label is secondary and the count is tertiary; the selected row shows its label and symbol in the primary colour and its count at 82% of primary, on a neutral wash (the primary colour at 12%, DESIGN section 2.2 `sel-side`) with the row radius, so the panel has one accent fill, on the selected result row, and not two. The sidebar is 184 pt wide so no Types name, "Phone Numbers" included, is cut with an ellipsis at the default size. The sidebar's scroll geometry works by lines: every line (a row or a section header) is 24 pt tall, there is a 4 pt top margin, the viewport is a whole number of lines tall and scrolling snaps to a line, so its bottom edge falls between two lines at rest and at every stop and never through one (at the 760 x 480 default the last visible line, Work with Types open, is whole). When the content is taller than the viewport (the Compact layout, and any small panel) the last visible line fades over 24 pt and one line of room follows the content, so the clipped end shows that the list scrolls and the far end of the scroll still lands on a line; when everything fits, nothing fades. Exactly one row is selected at a time; the selection is the single filter defined in FRD-004 FR-004-10. A row with count zero is shown dimmed except in Types, where empty types (Videos included) are hidden. The Types rows are the types listed in `library.types` (FRD-008 FR-008-26), in that order, each hidden while it has no items; a type switched off there has no row, and its items stay in All and in search. Videos is not an item type but a filter over files (FRD-004 FR-004-10), so `library.types` cannot list or switch it off: its row follows only the Videos count (shown at 1 or more, hidden at 0), never the Screenshots count. It sits right after Screenshots' place in the list; with Screenshots having no items it sits where Screenshots would be, and with Screenshots switched off it is the last Types row (TASK-561). Notes counts items that carry a note, Shortcuts counts items that carry a hotkey or a trigger, and Videos counts file and bundle items holding a video file (FRD-004 FR-004-10). The Bundles row is the "group" filter: a bundle is the one grouping kind (FRD-001 FR-001-12), so there is no second row for it.

**Preview**
- **FR-003-14** Preview pane (right side in the Standard layout, in place of the results in the Compact layout (FR-003-06), toggled by Space or ⌘Y, 280 pt wide in Standard, resizable with the panel). Content: text in full (up to 20,000 characters, then "Show more"); rich text rendered with its formatting (from its stored RTF; a rich text item with only HTML shows plain text, since importing HTML could fetch remote resources); link as the URL text only (no network fetch, no favicon, no metadata); colour as a large swatch with its hex and rgb values (for hex and `rgb()` notations; any other notation, and any malformed one (non-ASCII hex digits, an empty or non-numeric `rgb()` slot, a non-numeric alpha), shows its text and no swatch; out-of-range channels clamp to 0-255; colour notation, classification as a colour item as well as the swatch, takes ASCII digits only, so text with any other digits, such as Arabic-Indic or fullwidth, is plain text and not a colour; likewise a number too large to be a finite value, 309 or more digits, is plain text and not a colour), the hex and rgb values as the first rows of the metadata block after kind; image and screenshot scaled to fit; file, folder and bundle members as Quick Look previews with names (up to 20 members shown, then "and {n} more"). Below the content, a compact metadata footer pinned to the bottom of the pane (hill-climb r3 and r4: the content area takes all the height the footer leaves, and the footer is capped at 150 pt and scrolls inside itself past that). Kind, source app and the copied date and time are the summary: kind and source share one line separated by a middle dot, the copied date and time follows on the line below in the secondary colour. Every other field is a short label and value on one line: first-copied date, copy count ("Times copied"), paste count, size on disk, pixel size for images, the colour's hex and rgb, and the note; tags are chips (colour dot and name) that wrap, one per tag. Each field appears only when it has a value. The first-copied row appears only when it differs from the copied row (an item copied once has the same time in both), "Times copied" appears only above 1 (an item copied once says nothing by a count of 1) and "Times pasted" only above zero (hill-climb r1 and r3, TASK-529). Text that reads as code (more than one line, at least one line indented by a tab or two spaces) is drawn in a monospaced font with its indentation kept and no soft wrap, and scrolls sideways when a line is wider than the pane, with a 24 pt fade at the pane's trailing edge for as long as the text overflows, so the cut reads as intentional; prose and all other text wrap (`LibraryPreview.textIsIndented`). Preview is read-only. Opening preview never changes the selection. In the Compact layout the preview replaces the results only when exactly one row is selected in a loaded list; when the history is empty, a search has no results (FR-003-11) or the load failed (FR-003-20), the message (with Retry for a failed load) owns the results column and the preview gives way to it, and it returns when a row is selected again. Esc still closes the preview first (FR-003-08), and typing in the search field with results leaves the preview open.
- **FR-003-13** Thumbnails. Rows and cells display thumbnails produced by the storage pipeline (FRD-007 FR-007-07). A row whose thumbnail is not yet ready shows the kind icon and swaps when ready; scrolling never blocks on thumbnail generation. The in-memory thumbnail cache is capped at 64 MB (least recently used) and is emptied when the last panel (Library or Shelf) closes, so an idle app holds none (S5). One tracker (`PanelResidency`, FlotsamBase) is told by each panel when it opens and when it is gone (hidden and no longer drawing: the Shelf reports after its hide animation, so a fading card cannot refill the cache), and calls `FlotsamDatabase.releaseMemory()` once when the last open panel is gone; a panel that opens in between keeps what it loaded. A Library hide caused by the Shelf opening therefore releases nothing. Each panel also drops its own rows when it hides (FR-003-05), which is independent of the other panel.

**Paste-back**
- **FR-003-15** Paste sequence. On Return, ⌥Return, ⇧Return or ⌘1 to ⌘9: (1) if the item references files, resolve bookmarks and drop members that no longer exist; none left → `LIB-DAT-001`, no paste, panel stays open; (2) write the item to the general pasteboard: every stored representation for text-bearing kinds (plain text only for ⌥Return); the stored image data for image and screenshot kinds (written through `NSImage` so the system supplies standard image types); every existing member as a file URL for file, folder and bundle kinds; (3) mark the write as Flotsam's own (FR-001-03); (4) increment the item's `pasteCount` and set `lastUsedAt` (FRD-007); (5) hide the panel, unless `library.closeAfterPaste` is off (default on), in which case the panel stays open and the next step does not wait for it to hide; (6) for paste actions only: wait until the panel is no longer visible plus a settle delay of 40 ms, confirm the frontmost application is still the recorded target, then post ⌘V (key code 9 with the Command flag, key down then key up) addressed to the recorded target's process (`CGEvent.postToPid`), not to the session event tap (FR-003-16). ⇧Return performs steps 1 to 5 only, and is logged as `paste.copy`, not `paste.back` (FRD-000 FR-000-11).
- **FR-003-16** Target app mismatch or post failure. If the frontmost application is not the recorded target after 250 ms, or the event cannot be posted, the item stays on the pasteboard, nothing is pasted, and `LIB-OS-001` shows a HUD. A pasted item is never re-written after the event is posted. The ⌘V is addressed to the target's process, and the poster re-reads the frontmost application and the target's running state immediately before posting; if the target is no longer frontmost or no longer running, nothing is posted and the same failure applies. The session event tap is not used for ⌘V, because it delivers to whichever application has focus when the window server routes the event, so a focus change after the check would paste the clip into a different app (security finding F4, TASK-345). *Trade-off:* a process-addressed event bypasses the window server's focus routing, so it reaches the target's own event queue; this was chosen over the session tap because a misdirected paste leaks the clip, while a target that ignores a process-addressed ⌘V only fails to paste (the item is on the pasteboard and the user can press ⌘V). `postToPid` reports no delivery failure, so such a target shows no `LIB-OS-001`. Whether any target class (sandboxed, Electron, Terminal) ignores a process-addressed ⌘V is not yet confirmed; the dogfood matrix (Assumption 2) must include it, and if one does, the fix is a per-bundle fallback decided then, not a silent return to the session tap.
- **FR-003-17** Accessibility denied. When `AXIsProcessTrusted()` is false, paste actions perform steps 1 to 5 of FR-003-15 only (same as ⇧Return) and show the HUD `SET-PRM-001`; the HUD throttle (FR-000-08) may suppress repeats, so the footer hint bar also shows, while permission is missing, the persistent text `ui.library.footerCopyOnly` ("Press ⌘V to paste"), and the panel closes after Return as usual. Everything else in the Library works without Accessibility.
- **FR-003-19** Latency. Return to ⌘V posted: p95 ≤ 150 ms (`paste.back` signpost, which a copy-only paste does not emit because it posts no ⌘V), excluding the target app's own handling. Task falsifier (TRUTHS P1): hotkey to pasted, for a clip from yesterday located by typing, has a median ≤ 3 s in the timed dogfood task.

**Hints, data errors, accessibility**
- **FR-003-18** Footer hint bar shows the same four core keys while the list has rows, in this order: "Return Paste", "Space Preview", "⌥Return Plain Text" and "Esc Close", then the active sort's name (FR-004-12) beside the item count (both only while there are rows to sort and count, below), and the copy-only notice when applicable (hill-climb r1, TASK-529: one fixed set in fixed places, so the bar does not rearrange between states). Return Paste leads: its label is semibold in the primary text colour with an accent-tinted keycap, and the other hints are secondary (hill-climb r2). Keycaps are drawn in the system font. While the list has no rows to act on (an empty history or a search with no results) the hints that cannot act (Return, Space and ⌥Return) are not shown and only Esc Close stays, with the sort name and the item count hidden as well ("Recent 0 items" under a no-results message says nothing true; hill-climb r2 replaces r1's dimmed hints: a hint that cannot act is noise; r3 hides the empty count). With two or more rows selected the hints are "Return Start paste queue" and "Esc Clear selection"; while a paste queue waits (FR-003-25) the notice is its remaining count and that Esc cancels, in place of the copy-only notice (the Enable button stays). While Accessibility is denied (FR-003-17) the third hint is "⌘C Copy" (the copy-only key, FR-003-08) in place of "⌥Return Plain Text"; with Accessibility granted it stays "⌥Return Plain Text". Esc reads "Close" whether it closes the preview or the panel (FR-003-08). All text comes from the catalogue.
- **FR-003-20** Data errors. An item whose stored data is missing at paste time is deleted and shown as `LIB-IO-001`. A failed database read shows `STO-DB-004` inline in the results area with a Retry button; the panel keeps working.
- **FR-003-21** Accessibility. Every control is reachable and operable by keyboard; rows expose VoiceOver labels in the form "{kind}, {primary text up to 100 characters}, from {app}, {relative time}, pinned" with row actions available via the VoiceOver actions menu; the panel respects Reduce Motion (no slide, fade only), Increase Contrast, and light and dark appearance, with the panel's background following the system unless `library.background` is Light or Dark, which fixes the panel's appearance (FRD-008 registry); hit targets are at least 44 pt tall; a visible focus ring marks the selection.
- **FR-003-22** Context menu (right-click, mouse path only). Entries in order: Paste, Paste as Plain Text, Copy, Preview, separator, Pin or Unpin, Tags..., Note..., Edit... (text only), Shortcut and Trigger... (exactly one non-secure item), Group into Bundle (two or more file, folder or bundle items), Rename (exactly one bundle), Ungroup (bundle), separator, Reveal in Finder (where applicable), separator, Delete. Each performs the same action as its key in FR-003-08. Shortcut and Trigger... is shown only when the menu's target is exactly one item and that item is not secure; with several items selected it is absent, because ⌘K does nothing for them. A secure item's menu has neither Edit... nor Shortcut and Trigger... (FR-003-23, FR-005-09). The row and ⌘K follow one rule, so the row is offered exactly when ⌘K would open the editor. Note... and Edit... (exactly one item, Edit also a text kind that is not secure), Rename and Ungroup (exactly one bundle) likewise each follow one rule, shared by the menu and the Library's organize actions, so a row is offered exactly when its key would act (`ItemActionRule`, TASK-558). Group into Bundle follows the same one rule (`ItemActionRule.group`, TASK-565): it is offered only when the whole target (the selection when the menu opened on a selected row, else that row alone) is two or more file, folder or bundle items within the bundle member cap (FR-004-15); a selection the Group action would refuse, such as one that includes a text item or exceeds the member cap, gets no Group row. The App's editor entry point applies the shortcut rule itself too: it opens the editor only for exactly one id that is not a secure item, and otherwise opens nothing and leaves the Library as it is.
- **FR-003-23** Secure items: authorise, then re-copy. A secure item (FRD-001 FR-001-25) is shown as the fixed mask, never its text, with a lock; when its Keychain key cannot be read on this Mac the row also shows an "Unavailable" badge (the same catalogue string in the Library and the Shelf). Every action that would put its text on the pasteboard (Return, ⌥Return, ⇧Return, double-click, ⌘C, Paste, Paste as Plain Text and Copy in the context menu, and the Shelf's FR-006-21) first checks that the key is readable (`LIB-DAT-002` if not, and no prompt is shown, since nothing could succeed) and then asks the device owner to authenticate (Touch ID, Apple Watch or the account password), every time and with no grace period. A cancelled or failed check is `LIB-OS-002` and nothing is written, recorded or pasted. On success the text is decrypted only then and written as plain text alone (the mode does not matter) with `org.nspasteboard.ConcealedType` plus the own-write markers (FRD-001 FR-001-03), so other apps and clipboard managers treat it as the password it is, Flotsam does not capture its own re-copy, and the clipboard-variable `{clipboard}` (FRD-005 FR-005-17) reads it as empty. Accepted trade-off: because the item is re-copied to the general pasteboard, a password manager's own auto-clear of the clipboard no longer limits how long the password is exposed there.
- **FR-003-24** Relative times stay current. While the panel is shown, every row's relative time (FR-003-07) and the age in its VoiceOver label (FR-003-21) advance without any other input: a row that read "2m ago" reads "3m ago" a minute later with the panel still open. Both strings are built from one reading of one clock per refresh, so they never disagree. A refresh is due when the soonest visible label would read differently, and every label is right within one step of a clock change: each second for a copy under a minute old ("5s ago"), then each minute and each hour, then each calendar day (counted on the calendar, so a day is 23 or 25 hours long across a daylight-saving change, but the refresh for the last day label is never later than the second the copy turns 7 days old, 604,800 s, so it becomes a date on time); a copy dated ahead of the clock (the clock was set back) reads "now" and is next refreshed a second after its date, not every second until then; a copy more than 7 days old reads as a date and never needs one. While the panel is hidden nothing is scheduled (idle wake-ups stay within FRD-001 FR-001-20, which counts only a hidden panel), and showing the panel reads the clock afresh.
- **FR-003-38** Hover row actions (mouse path only; every key and the context menu are unchanged). While the pointer is on a row (list) or cell (grid), a small strip appears on it with three buttons, in order: Copy, Pin or Unpin, Delete. The strip sits over the row's trailing end, so a hovered list row reserves that space (86 pt, `LibraryLayout.hoverStripReserve`) and its title truncates instead of running under the buttons; the Delete glyph is neutral until the pointer is on it, then red. Each is the context menu's entry of the same name (FR-003-22) and acts on the row exactly as that entry does: it acts on the pointer's row, or on the whole selection when that row is part of a multi-selection, selecting the row first when it is not selected. Pin or Unpin reads the same rule as the menu's entry. Delete takes the same path as Delete in the menu and ⌘⌫. The strip is drawn only for the hovered row, never changes the selection or the cursor by the pointer merely resting there, has a tooltip with each button's name, and is hidden from VoiceOver (the keys and the context menu are the accessible path, FR-003-21). While the strip shows, the row's own trailing badges and its ⌘1 to ⌘9 index give way to it (hill-climb r3), so a pinned row shows one pin, the strip's Unpin, and never a second beside it; they return when the pointer leaves.
- **FR-003-39** Hover preview (mouse path only). When the pointer has rested on a row for 500 ms and the preview pane is closed (FR-003-14), the same preview content as the pane (FR-003-14) appears as a read-only card beside that row: below it, or above it when there is no room, never over the row or its strip. Moving to another row restarts the wait; leaving the row, any key or command, opening the preview pane (Space or ⌘Y), hiding the panel and opening it again all dismiss the card, and a row the pointer is still on does not bring it back until the pointer enters a row afresh. It does not change the selection or the cursor, takes no pointer input, loads nothing from the network (FR-003-14), and a secure item shows its mask only (FR-003-23). It adds no timer while the panel is idle: the wait exists only between the pointer entering a row and leaving it (S5). The Esc order (FR-003-08), the keys and the Space and ⌘Y preview are unchanged.
- **FR-003-25** Paste queue. Select two or more rows and press Return: the Library closes and those items, in list order, wait as a queue. Each press of the Paste Queue shortcut (`shortcuts.pasteQueue`, FR-005-01) pastes the next item into the frontmost app through the same sequence as a single paste (FR-003-15 to -17, including secure-item authentication, FR-003-23, and the pasteboard restore), so the queue is not a second paste path. The queue advances only after that item was pasted or, without Accessibility, copied (FR-003-17); an item whose paste fails with a transient error (for example the user switched apps, `LIB-OS-001`) stays at the head and the next press retries it, and an item that can no longer be read (`LIB-IO-001`, `LIB-DAT-001`, `LIB-DAT-002`) is reported and dropped. Without Accessibility each press copies the next item and shows `SET-PRM-001`; the user pastes with ⌘V. A short HUD reports the queue starting ("Paste queue ready: N items"), progress ("Pasted n of N"), finishing and cancelling. Esc in the Library cancels the queue (the last step of the Esc ladder, FR-003-08); starting another queue replaces it. A press with no queue shows "The paste queue is empty". With the Paste Queue shortcut unbound, Return with several rows selected shows "Set a Paste Queue shortcut in Settings first" and keeps the panel open. The queue is in memory only (gone at quit), adds no monitor or timer, and writes nothing to the library. All text comes from the catalogue.
- **FR-003-45** Drag out of rows. Dragging a row (list or grid) past the system drag threshold starts a standard drag session, the same one the Shelf uses (FRD-006 FR-006-10, FR-006-11: representations, `.copy` only, the drag pasteboard only, lazily provided, never captured as a clipboard change, the stacked drag image with a count badge, the outcome codes and their HUD rules). Which rows go: if the row is in the selection, the whole selection in on-screen order; if it is not, that row alone and the selection is unchanged. A plain click still selects and a double-click still pastes (FR-003-09, FR-003-15); a press that does not pass the threshold reads nothing. An accepted drop counts one paste per dragged row (FR-003-15 count rule, `pasteCount` and `lastUsedAt`) and hides the panel, as a paste does; a drag that is cancelled or dropped on nothing changes nothing and leaves the panel open. A secure row (FR-003-23, FR-006-21) asks the device owner to authenticate when the drag starts (past the threshold, never on a plain click or a selection change), every time with no grace period, and the key-readable check comes first (`LIB-DAT-002`, no prompt); the text is decrypted only after that and is offered as plain text with `org.nspasteboard.ConcealedType`. A cancelled or failed check (`LIB-OS-002`) skips that row like a row with nothing to drag; if no row remains, no drag starts and the error shows; releasing the mouse button while the prompt is up starts no drag. The prompt taking key from the panel is not a click outside, so the panel stays open for it. A Library drag dropped on the Shelf is an ordinary drop (FR-006-12, FR-006-13); the Shelf refuses only drags that began in the Shelf. When a drag begins, the hover strip and hover preview card (FR-003-38, FR-003-39) are dismissed; a press on a hover-strip button, or in the gaps of the strip, acts as that button or does nothing and never starts a drag. Drag-out has no keyboard equivalent: Paste and Copy are the keyboard paths. Reuses `ShelfDragOut`; no timer, no observer and no network use.

## 4. Data Requirements
- Reads items, tags, source apps and counts through the storage query layer (FRD-007); writes only `pasteCount` and `lastUsedAt`.
- Settings read (FRD-008 registry): `library.viewMode`, `library.panelSize`.
- In memory: target app (bundle id, pid), selected item ids, current query, cache of 50 newest rows, thumbnail LRU (64 MB); the row cache (the loaded rows and the preview pane's content) is released when the Library hides, and the thumbnail LRU when the last panel closes (S5, FR-003-13); a reopen inside the resume window reloads the rows and keeps the selection (FR-003-04).

## 5. Business Rules
- Paste-back never modifies stored items (no re-save of what was pasted).
- Paste count increments on every successful pasteboard placement from the Library, including ⇧Return and the Accessibility-denied fallback, and once per row for each accepted drag-out (FR-003-45).
- The panel never makes a network request.
- Search matches the text the system recognised in an image or screenshot (FR-003-55) and nothing else about its pixels. Recognised text is for search only (A3): it is never displayed, edited, exported, copied or put on any pasteboard or drag.
- Dragging out of a row never moves, renames or deletes an original file (the operation is copy), never writes the general pasteboard, and never puts a secure item's text on the drag pasteboard without the owner's authentication (FR-003-45).

## 6. Error States (codes in FRD-000 §7)
| Situation | Code | Behaviour |
|---|---|---|
| Target app changed or ⌘V could not be posted | LIB-OS-001 | item left on pasteboard; HUD |
| Stored data missing | LIB-IO-001 | item deleted; HUD |
| Referenced files all missing | LIB-DAT-001 | no paste; HUD; row marked Missing |
| Secure item copy not authorised | LIB-OS-002 | nothing written to the pasteboard; HUD (FRD-001 FR-001-25) |
| Secure item key missing or bytes unreadable | LIB-DAT-002 | no copy; HUD; row marked Unavailable |
| Accessibility not granted | SET-PRM-001 | copy-only; HUD and footer hint |
| Database read failed | STO-DB-004 | inline message with Retry |

## 9. Assumptions to verify (architecture spikes)
1. A non-activating `NSPanel` that is key accepts text input while leaving the previous app frontmost, on macOS 26, including over full-screen apps.
2. The 40 ms settle delay and 250 ms window are sufficient across Terminal, Electron and browser targets; tune from the dogfood matrix.
3. Search at 10,000 items meets 100 ms with SQLite full-text indexing; the index design is FRD-007's (spike confirms trigram or scan strategy).
4. The default open-Library hotkey (FRD-005) does not collide with common system or app shortcuts.

## 10. Out of Scope
Remappable in-panel keys. Relevance ranking, search operators and saved searches. Pasting several selected items at once. Link metadata, favicons or any network preview. Showing, editing, exporting or copying out the text recognised in images (A3: that text is for search only, FR-003-55). Sharing or AirDrop (NOT DOING).
